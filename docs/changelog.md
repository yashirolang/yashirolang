# 版の記録

yashirolang の各版で何が変わったかです。いまの版は `yashirolang --version` で分かります。
（これから入れるものは [roadmap.md](roadmap.md) にあります。）

| 版 | 内容 |
|---|---|
| **0.34.0** | **インタフェース越しに `raises` が通るようになりました**（A-40）— 0.33.0 までは「`raises` するメソッドを持つクラスはインタフェース越しに呼べません」と断っていました。**失敗しうる操作を差し替えられない**——書き出し先を差し替える `Writer`、再試行する `Transport` が型で表せない——という穴だったので埋めました。★ 通し方は簡単でした。`raises` 関数は**末尾にエラー出力引数が 1 本増えるだけ**なので（0.17.0 の判断）、vtable から読んだ関数を**同じ段取りで呼べば**済みます。codegen の追加は「呼び出しを出すところを、呼び先（名前かレジスタか）を受け取る形に一般化する」1 か所だけでした。★ **投げうるエラーは宣言で固定します。** 実装には同じ `raises` を求めます——多くても少なくてもエラーです。呼ぶ側はインタフェースの宣言しか見ないので、実装ごとに違うと `try` を書く手がかりが無くなります。★ 注意: **関数型（`fn(...)`）は据え置き**です。あちらには `raises` を書く欄が無く、値にできません。★ 見つけた不具合: インタフェース越しの呼び出しは、もともと**エラースロットを渡さないまま**呼べてしまう形でした（呼び先は 3 引数、呼び出しは 2 引数）。断っていたので表に出ていませんでしたが、通す側に回った時点で踏みます。番人は `iface_raises<ext>` / `err_iface_raises_less<ext>` / `err_iface_raises_more<ext>` / `err_iface_raises_untried<ext>` |
| **0.33.0** | **`lambda` が入りました**（A-42）— `count_if(xs, lambda x: x > 0)` と書けます。★ **型を書きません。** 引数と戻り値の型は「置かれた場所」（型注釈のある変数・関数型の引数・戻り値・フィールド）から決まります。書かせると `lambda x: int -> bool: x > 0` のような形になり、**短く書くための機能なのに def より長くなります**。★ 仕掛けは**ジェネリック関数の単相化の再利用**です——パーサが `.T0` / `.R` という型引数を作って lambda をテンプレートとして持ち上げ、sema が使う側の型を束ねます。**新しい仕組みを足していません**（同じ lambda を違う型で使えば実体が 2 つできるのも、ジェネリック関数と同じです）。★ **捕獲（クロージャ）はまだありません。** lambda はトップレベルの関数に持ち上げるので、外の変数はそこから見えません（グローバルは使えます）。捕獲を入れるには「関数と、捕まえた値の入れ物」が要り、この言語は**借用を構造体に保存できない**ので（A-39 で `for` にイテレータ物体を作らなかったのと同じ理由）、`fn(...)` 型の**表現そのものを決め直す**ことになります。表現を変える話は版を分けます。★ 断る側を 3 つ足しました：外の変数の捕獲／型が決まらない置き場所／引数の数違い。とくに捕獲は「未定義の名前です」で突き放さず、**何が起きたのか**を言います。番人は `lambda_basic<ext>` / `err_lambda_capture<ext>` / `err_lambda_no_type<ext>` / `err_lambda_arity<ext>` |
| **0.32.0** | **`for` の規約が入りました**（A-39）— 利用者のクラスを `for` で回せます。`__first__` / `__next__` / `__get__` の 3 つを書くだけです。★ **カーソルは `int` だけ**で、イテレータ物体は作りません——この言語は**借用を構造体に保存できない**ので（寿命注釈を入れないと決めたため）、容器を指すイテレータを作ると容器を `rc[T]` にするか、寿命を書かせることになります。カーソルなら容器は借りたままで、ループが持つのは `int` 1 つです。★ **`dict` と `set` に付けました。** `for k in d:` が**読み取り専用の借用のまま**回せます——`keys()` は詰め直し（compact）のために `mut self` が要るので、`def total(d: Dict[str, int])` のような「読むだけの関数」からは回せませんでした（E-MUT-1）。消えた要素は詰めずに飛ばします。★ 穴のある容器も、`mut self` で書けば**流れてくるもの**（行・受信）も同じ形で表せます。★ **脱糖の場所を sema へ移しました。** `for` の形は対象の型で変わる（list / str なら添字、クラスならカーソル）ので、パーサでは決められません。隠し変数の名前だけはパーサが採るようにして、**既存の `for` が出す IR はバイト単位で不変**であることを確かめています。★ 副産物として `for x in 42:` のエラーが直りました——「len は 'int' 型を受け取れません」（利用者が書いていない `len` が漏れていた）から「'int' 型は for で回せません」へ。★ **インタフェースの実装に、宣言と同じ引数名を求める**ようにしました（0.31.0 で引数の名前が呼び出し側から見える約束になったため）。番人は `iter_protocol<ext>` / `iter_dict_set<ext>` / `err_iter_no_protocol<ext>` / `err_iter_bad_sig<ext>` / `err_iface_param_name<ext>` |
| **0.31.0** | **既定引数とキーワード引数が入りました**（A-38）— ロードマップの言語機能の 1 番でした。引数が増えた API（`pad(s, n, c, right)`）が、呼び出し側で「3 番目は何だったか」を数えずに使えます。★ **既定値に書けるのはリテラルだけ**です（数・文字列・`True` / `False` / `None`・列挙の枝・符号つきの数）。Python の `def f(xs=[])` は、その list が**呼び出しをまたいで共有**されます——リテラルだけにすれば、**その形がそもそも書けません**（list が要るときは `xs: list[int] \| None = None` と書いて中で作ります）。★ もう 1 つの理由は**名前の解決先**です。`n: int = len(XS)` の `XS` は定義側の名前か、呼び出し側の名前か。既定値は**呼び出し側に置き換える**作りなので、名前が入ると答えが 2 つになります。★ **並べ替えと穴埋めは意味解析で 1 か所**（`bind_args`）にまとめました。ここを通ると `n->args` は「ちょうど引数の数だけ・定義の順」になるので、**型検査・codegen・所有権検査・証明は 1 行も変わりません**（「呼び出しの形を知るのはこの関数だけ」）。★ 既定値は**呼び出しごとに複製**します（定義時に 1 つ作って共有しません）。★ **名前で渡せるのは呼び先がソースから 1 つに決まるとき**だけです——組み込み（`print`）・関数の値（`fn(int) -> int`）・インタフェース越しには渡せません。とくにインタフェースは**どの実装が呼ばれるか実行時に決まる**ので、宣言に既定値を書くこと自体を断ります。★ ジェネリック関数では**型引数を決める前に**並べ替えます（並びが定義どおりでないと、`T` が別の引数から決まります）。★ **断る側を 12 個**足しました：リテラル以外の既定値（list / 変数 / 呼び出し）／型の合わない既定値／既定値のある引数より後ろの必須引数／無い名前／2 回渡し／名前の後ろの位置引数／渡されていない必須引数／組み込み・関数の値・インタフェース越しのキーワード／インタフェース宣言の既定値。注意: **`ast_clone` が畳んだ列挙の枝（`en`）を写していませんでした** — 写さないと、複製した既定値が `Level.High` からただの `int` に戻ります（A-37 の畳み込みと A-38 の複製が初めて出会った場所です）。番人は `default_args<ext>` / `kwargs<ext>` と `err_default_*` / `err_kwarg_*` / `err_iface_default` の 13 件 |
| **0.30.0** | **`enum` と `match` が入りました**（A-37）— ロードマップの言語機能の 1 番でした。状態機械・エラー種別が、グローバル定数の束ではなく**型**になります。★ **枝は名前だけ**です（中身を持つ枝はまだありません）。番号も書かせず、宣言順に 0 から振ります——書けるようにすると「番号を合わせるために枝を並べ替える」コードが生まれ、枝を足すのが怖い変更になるためです。★ **表現はただの i64** で、vtable も割り付けも増えません（「値はどれも 8 バイト」の前提に触りません）。★ `TY_ENUM` は**独立した種別**にしました。範囲型が `TY_INT` のままなのとは**逆の判断**です——範囲型は「int の一種」なので混ざるべきですが、列挙は `c + 1` や `c == 0` を**通してはいけません**。同じ種別にすると既存の `kind == TY_INT` の判定が全部「列挙も通す」意味になり、**書き忘れた場所が静かに通ります**。★ **網羅の検査がこの機能の本体です** — 枝を落とすと「match に書いていない枝があります: Color.Green / Color.Blue」で止まります。枝を足したとき、**直す場所をコンパイラに挙げさせる**ために入れました。確かめないなら if の連なりと同じで、入れる意味がありません。★ `match` は列挙のほか **int / str** でも使えます（str は**内容**で比較）。値が無限にあるので **`case _` を必須**にしました。★ **断る側を 6 つ**足しました：列挙と int の混在／無い枝／枝の書き漏れ／`case _` 無し／同じ値の case 2 つ／`case _` より後ろの case。★ `match` は**比べる連なりに落とすだけ**で、IR に新しい形を増やしていません（`elif` と同じ）。**調べる式は 1 回しか評価しません**（`match f(x):` で f を case の数だけ呼ぶと、副作用のある関数で答えが変わります）。箱（alloca）も作りません——箱にすると str を調べたときに「その箱は誰のものか」という所有権の話が要ります。★ `enum` と `case` は**柔らかい予約語**です（`scope` と同じ扱い。`case` は「試験の 1 件」のような普通の名前なので予約語にしません）。注意: **`always_returns` に `match` を教える必要がありました** — 入れないと、全部の case で return しているのに「値を返さない経路があります」と言われます（`try` が 0.17.0 で踏んだのと同じ穴）。番人は `enum_match<ext>` と `err_enum_*` / `err_match_*` の 6 件 |
