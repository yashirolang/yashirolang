# CI の作りと、速くするために入れた工夫

**★ この文書は「なぜその形なのか」を残すためのものです。**
CI は落ちたときにしか読まれないので、意図を書いておかないと、
あとから「無駄に見える一行」を消されてしまいます。

## 何を回しているか

| | 中身 | どの OS |
|---|---|---|
| ⓪ | `make check-naming` — 言語名が書き写されていないか | Linux のみ |
| ① | `make -j …` — コンパイラ（stage0）を建てる | 3 つすべて |
| ② | `make test` — 629 件 + 解放の検査 + **2 実装の IR をバイト比較** | 3 つすべて |
| ③ | `make bootstrap` — 3 段ビルドと不動点（stage2 == stage3） | 3 つすべて |
| ④ | `make bootstrap-test` — セルフホスト版で 629 件を**もう一度** | Linux のみ |

注意: ⓪ は**いちばん先**に置いています。0.3 秒で終わり、落ちたら以降を
回す意味がないためです（実際に 0.26.0 と 0.27.0 で落ちました）。

## Windows が遅かった理由と、入れた手当て

Windows のジョブは 19 分かかっていました。**ランナーの性能差ではありません。**
原因は「短命プロセスを大量に作る作り」と、Windows でのプロセス生成の高さ
（MSYS2 は POSIX の `fork` をエミュレートします）の掛け算です。

| 手当て | なぜ |
|---|---|
| **期待値を awk 1 回で読む**（`tests/markers.awk`） | 以前は 1 ケースにつき `sed` 11 回・`tr` 4 回・`grep` 1 回。629 件で**1 万プロセス近く**を毎回作っていました |
| `tests/selfhost.sh` も同じく awk 1 回 | こちらも 700 件近く回るので、`sed` と `head｜grep` で 2,000 プロセス以上 |
| `update: true` をやめ `cache: true` に | 毎回 `pacman -Syuu` で基盤ごと更新すると数分かかり、パッケージのキャッシュも毎回無効になります。★ 要るのは clang と lld と make だけです |
| Defender の走査から作業場所を外す | 629 件ぶんの `.ll` / `.o` / 実行ファイル を書きます。注意: 権限が無い環境でも CI は通すべきなので `continue-on-error` です |
| `make -j$(getconf _NPROCESSORS_ONLN)` | `make` 単体は逐次です。注意: 並列数は**機械に訊きます**（ランナーの大きさが変わっても CI を直さずに済みます） |
| ④ を Linux だけにする | テスト 629 件を**もう一度**通すので仕事がほぼ倍になります。★ 2 実装が同じ IR を出すことは ② が**バイト単位で**確かめており、そこは 3 OS すべてで回ります |

### 測った結果（`make test` 全体。Intel Core i7-9750H / macOS）

| | real | user | sys |
|---|---|---|---|
| 前 | 679.8 秒 | 166.9 秒 | 140.9 秒 |
| 後 | **641.7 秒** | 143.0 秒 | **104.6 秒** |
| 差 | −5.6% | −14.3% | **−25.7%** |

★ **`sys` が 26% 減ったのが、狙いどおりに効いた証拠です**（プロセス生成は
カーネル側の仕事なので、ここに出ます）。

注意: **Windows での実測値はここにはありません。** 手元に Windows がないので、
「プロセス生成が Linux より高い Windows では、同じ削減がもっと効くはず」
という**予想**です。実際の値は CI の所要時間で確かめてください。

注意: real が 5.6% しか縮まないのは、残りをコンパイラと clang の実行が
占めているからです。**ここから先を縮めるなら、プロセスの数ではなく
1 プロセスの中身を減らすことになります**（例: 1 回のコンパイラ起動で
複数ケースを見る）。まだ手を付けていません。

## 触るときの約束

- 注意: **`update: true` を戻さないでください。** 直す理由があるなら、
  戻す代わりに `install:` へ必要なパッケージを足してください
- 注意: **④ を 3 OS に戻さないでください。** 戻すなら ② の IR 比較が
  OS ごとに違う結果を出しうる、という根拠を先に示してください
- ★ 名前（言語名・拡張子・コマンド名）は **make に訊きます**。
  CI に書き写すと、改名のたびに CI を直すことになります
  （[naming.md](naming.md)）
