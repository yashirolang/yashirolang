# 捕獲（クロージャ）の設計メモ

> `lambda` は 0.33.0 で入りました（[spec/language-spec.md §4.5.2](../spec/language-spec.md#452-lambdaa-42)）。
> **捕獲だけがありません。** ここでは「なぜすぐ入らないのか」と「入れるなら
> どの形か」を決めます。決めるのは**表現**で、構文ではありません。

---

## 1. なぜ表現の話になるのか

いまの `fn(A) -> B` は**生の関数ポインタ**です（IR では `ptr`。`llvm_type` の
`TY_FN`）。値はどれも 8 バイト、という前提に乗っています。

捕獲した値を持ち回るには「**関数と、捕まえた値**」の組が要ります。組は 8 バイトに
入らないので、**どこかに置いて、そこを指す**ことになります。つまり `fn` の表現を
決め直す話です。

そして、この言語は**借用を構造体に保存できません**（寿命注釈を入れないと決めたため。
[ownership.md](ownership.md)）。だから捕獲は次のどちらかにしかなりません。

- **複製する**（値型はそのまま写す。`str` / `list` は `copy`）
- **所有権ごと渡す**（`own`）／**`rc[T]` で共有する**

「外側の変数を参照し続ける」Python のクロージャは、この言語では**書けません**。
そこは諦める前提で設計します。

---

## 2. 案

### 案 A: クロージャ物体（新しい種別を作る）

`fn` の値を `{ 関数ポインタ, 捕まえた値… }` という物体へのポインタにします。

- 素の関数を `fn` に入れるときは、**静的な物体**を 1 つ用意して指します（確保なし）
- 呼ぶときは物体から関数ポインタを読み、物体自身を隠し第 1 引数として渡します
- 素の関数には、その呼び方に合わせる薄い包み（thunk）を 1 つ生成します

### 案 B: `fn` をインタフェースにする（既存の仕組みに寄せる）

`fn(A) -> B` を**インタフェース型として扱います**。この言語のインタフェース値は
すでに「vtable を埋めた物体へのポインタ」です。

- lambda ごとに**隠しクラス**を作ります。捕まえた値が**フィールド**になります
- 捕獲なしの lambda と素の関数は、**フィールドを持たない静的な実体**にします
  （確保なし。いまと同じ速さ）
- 呼び出しは vtable 越し。**新しい呼び出し規約を作りません**
- 寿命・解放は**クラスと同じ扱い**になります（drop の仕組みがそのまま効きます）

新しい機械を足さないぶん、案 A より案 B が良いのですが、**どちらもヒープに
物体を作る**ので、次の §3 の代償（利用者のコードが壊れる）から逃げられません。

### 案 C: 枠の上に置く（確保しない）★ 採用

**捕獲した lambda を、作った関数の枠（スタック）に置きます。**

```
    f: fn(int) -> bool = lambda x: x > n

    枠の上:  [ code = @lambda.0.thunk | n の写し ]
                        ↑ fn の値は、この記録を指すポインタ
```

- 素の関数を `fn` に入れるときは、**静的な記録**を 1 つ用意して指します
  （中身は関数ポインタだけ。確保もカウントもありません）
- 捕獲する lambda は、**枠の上に記録を作ります**（`alloca`。確保しません）
- 呼ぶときは記録から関数ポインタを読み、**記録自身を隠し第 1 引数**として渡します
- 素の関数には、その呼び方に合わせる薄い包み（thunk）を 1 つ生成します

**寿命はどうなるのか。** 枠の上にあるので、**作った関数より長生きできません**。
つまり「借りもの」と同じ性質です——この言語はすでに
「借用は呼び出しより長生きしない」で通しているので（[ownership.md](ownership.md)）、
**新しい考え方を足していません**。逃がそうとしたら（返す・フィールドにしまう・
グローバルに入れる）、コンパイル時に断ります。

| | 案 A / B（ヒープ） | 案 C（枠の上）★ |
|---|---|---|
| 確保 | 捕獲のたびに 1 回 | **しません** |
| 解放・カウント | 要ります | **要りません**（枠が畳まれるだけ） |
| 既存のコード | **壊れます**（`own fn` を書かせる） | **壊れません** |
| できないこと | — | 捕獲した lambda を**返す・しまう**こと |

できないことは残りますが、**できない形はコンパイル時に断れます**。黙って
壊れる道がないなら、まずここまでを入れるのが順当です。

## 3. 案 A / B の代償（案 C を採った理由）

**`fn` 値が「物体」になるので、所有権の扱いが変わります。** いまの `fn` は
ただの値で、写しても誰も困りません。物体になると、既定が借用になります。

```python
class Button:
    on_click: fn(int) -> int

    def init(self, on_click: fn(int) -> int) -> None:
        self.on_click = on_click        # ← いまは通る。案 B では E-BORROW-3
```

つまり **既存のコードが「`own fn(...)` と書き直し」を迫られます**。
いま `fn` を持ち回っているのは `lib/http`（要求を捌く関数）・`lib/lists`・
`lib/stats`・`lib/numeric` と、そこを使う利用者のコードです。

選べる道は 3 つあります。

| 道 | 中身 | 代償 |
|---|---|---|
| ① 破る | `fn` を物体にし、必要な場所に `own` を書かせる | **既存のコードが壊れます**（書き直しは機械的ですが、利用者にも及びます） |
| ② 分ける | 捕獲のある lambda だけ別の型（例 `closure(A) -> B`）にする | 型が 2 つになり、「どちらを書くのか」を利用者が覚えることになります |
| ③ 入れない | 捕獲は諦め、状態はインタフェースで書く | いまのままです。`lambda` は捕獲なしで使えます |

**どれも代償が大きいので、案 C（枠の上）を採りました。** 標準ライブラリを
数えたところ、`fn` を**フィールドにしまっている場所は 1 つもありません**
（`http` も `numeric` も `stats` も、受け取って**呼ぶだけ**です）。
つまり案 C で困る場面は、いまのところ実在しません。

案 C で足りなくなったら（捕獲した関数を**しまいたい**とき）、そのときに
案 B ＋ ①を考えます。**壊す変更は、必要になってから**入れます。

---

## 4. 案 C で決めたこと

| 決めたこと | 理由 |
|---|---|
| 捕まえられるのは**値型だけ**（`int` / `float` / `bool` / 列挙 / 範囲型） | `str` や `list` を捕まえると「借りものを持ち回る」話になり、借用の寿命の検査が要ります。まずは黙って壊れない範囲から入れます |
| 捕獲は**作ったときの値の写し** | 呼ぶときに外の変数がどうなっているかを気にせずに読めます（捕まえた後に外を書き換えても、写しは変わりません） |
| 捕獲した lambda は**返せない・しまえない** | 枠の上にあるためです。断り方は「捕獲した lambda は、作った関数より長生きできません」 |
| 引数として**渡せる**（`count_if(xs, lambda x: x > n)`） | 呼び先が**しまわない**ことを確かめます（所有権検査が見ます） |
| 素の関数の値（`f` をそのまま渡す）は**今までどおり** | 静的な記録を指すだけなので、寿命の制限はありません |

## 5. 残っていること

- **`str` / `list` / クラスの捕獲**。借りたものを枠の上に置く形になるので、
  「捕まえたまま元を動かせない」という検査が要ります
- **捕獲した lambda をしまう**（案 B ＋ 破壊的変更）。必要になってから
- 捕獲を**明示に書かせるか**（`lambda[n] x: x > n`）。いまは黙って捕まえます
