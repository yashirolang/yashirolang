## 1. 何を足すか（最小の 4 つ）

| 足すもの | 形 | 役割 |
|---|---|---|
| `spawn` | `t: Thread = spawn(f, arg)` | 関数を別スレッドで始める |
| `Thread.join` | `r: T = t.join()` | 終わるまで待って戻り値を受け取る |
| `mutex[T]` | `m: mutex[Counter]` | **中身に触るには必ずロックを通す** |
| `with` 相当 | `m.lock(fn)` | ロックを取り、渡した関数を呼び、必ず解く |

⚠️ **`async` / `await` というキーワードは入れません。** ただしこれは
「非同期を諦めた」という意味ではありません。**下の §6 に、あとから
利用者のコードを変えずに非同期を得る道を書いてあります。**

⚠️ ~~クロージャが無いので `spawn` は「関数 + 引数 1 つ」の形になります~~

✅ **この制限は撤回しました。`spawn` は引数を何個でも取ります。**
「1 つにまとめるのは検査に都合が良い」と書いていましたが、**逆でした**。
まとめる先はクラスしかなく、**クラスは借りを保存できません**（`E-BORROW-3`）。
つまりこの形のままでは、[§7](#7-scoped-spawn実装-) を入れても
**借りを共有する形が書けません**。可変長にして解きました。

```python
scope:
    t: Thread[list[float]] = spawn(rows, a, b, n, lo, hi)   # 借り 2 つ + 値 3 つ
```

## 2. 検査の規則 — 所有権の検査をそのまま延長する

**新しい注釈は 1 つも足しません。** すでにある `own` / `mut` / 借用の規則に、
**「スレッドの境界を越えられるか」という 1 つの問いを足すだけ**です。

### 2.1 スレッドに渡せるもの

| 渡すもの | 可否 | なぜ |
|---|---|---|
| `own T`（所有を手放す） | ✅ | 渡した側はもう触れない。競合しようがない |
| `mutex[T]` の共有 | ✅ | 触るにはロックが要る |
| **借り（既定の引数）** | ❌ | 借りは「呼び出しより長生きしない」規則で守られている。スレッドは呼び出しより長生きしうる |
| `rc[T]` | ❌ | **参照数の増減が競合する**（下記） |
| グローバル変数への書き込み | ❌ | 誰が触っているか静的に分からない |

**⚠️ ここが要点です。** 借用検査がすでに持っている
「借りは呼び出しより長生きしない」という不変条件が、そのまま
「借りはスレッドに渡せない」に翻訳されます。**規則を足すのではなく、
既にある規則の帰結として出てきます。**

### 2.2 `rc[T]` はスレッドをまたげません

`rc[T]` の参照数はただの整数の増減で、**競合すると数が壊れます**
（早すぎる解放＝解放後の使用）。原子的な増減にすれば直りますが、
**すべての `rc[T]` が遅くなります**。コンパイラ自身が `rc[T]` だらけなので、
これは払えません（[rc[T] 移行](../roadmap.md#優先度-a-14--コンパイラ自身を-rct-へ移す345--0-件-)）。

**だから分けます。**

| 型 | 参照数 | スレッド |
|---|---|---|
| `rc[T]` | ふつうの加減算 | **1 つのスレッドの中だけ** |
| `arc[T]`（新設） | 原子的な加減算 | またげる |

⚠️ `arc[T]` を入れるかは**後で決めます**。まず `own` を渡す形と `mutex[T]` で
足りるかを見ます。足りるなら型を 1 つ増やさずに済みます。

#### ⚠️ 実装で気づいた穴 — 「中に」ある `rc` も止めます

`own Job` を渡すのは安全に見えます。ところが `Job` のフィールドに
`rc[Node]` があれば、**その数え札は 2 つのスレッドから増減されます**
（渡した側が、同じ節点への `rc` を別に持っていることがあるため）。

**渡すものの型だけを見て「クラスだから安全」とは言えません。**
`E-SEND-2` は、渡す型から**たどれる範囲すべて**（クラスのフィールド、
`list` の要素、タプル、`T | None`、`mutex` の中身）を探します。
再帰的なクラスで止まらないよう、たどったクラスは覚えながら降ります。

⚠️ `mutex[T]` に入れても逃げられません。**ロックが守るのは中身で、
数え札は `rc` が指す先（箱の外）にある**ためです。

### 2.3 診断コード

既存の `E-MOVE-1` / `E-BORROW-*` / `E-MUT-1` に並べて足します。

| コード | 意味 |
|---|---|
| `E-SEND-1` | 借りをスレッドに渡そうとした |
| `E-SEND-2` | `rc[T]` をスレッドに渡そうとした（⚠️ **中に持っているだけでも**止まります。上の 2.2） |
| `E-SEND-3` | グローバル変数をスレッドから書き換えている |
| `E-SEND-4` | 可変借用をスレッドに渡そうとした |

**常にエラーです**（警告に落とす手段はありません）。所有権検査そのものも
0.18.0 から既定でエラーになりました（A-24）が、**`--warn-own` で警告へ
落としたときも、ここだけは落ちません**。

**✅ 2 つの実装のどちらでも同じ検査をします**（A-25。0.18.0）。
それまで `E-SEND-*` は C 版にしかなく、**どちらのコンパイラで建てたかで
保証が変わっていました**。診断の文面を 1 文字も変えずに移植したので、
`tests/selfhost.sh` の突き合わせがそのまま見張りになります。

## 3. 実装の置き場所

```
   lexer → parser → sema → ownck（★ここに送出可能性の検査）→ codegen
                                                                 │
                                            runtime/hosted.c ────┘
                                            （pthread / Win32 の薄い層）
```

| 変えるところ | 中身 |
|---|---|
| `parser` | `spawn` は**関数呼び出しの形のまま**（新しい構文を作らない） |
| `sema` | `spawn(f, a)` の型付け：`fn(A) -> R` と `A` から `Thread[R]` |
| `ownck` | **送出可能性の検査**（上の 2.1）。`spawn` の引数を「ムーブされた」と記録する |
| `codegen` | `pl_thread_spawn` / `pl_thread_join` / `pl_mutex_*` の呼び出し |
| `runtime/hosted.c` | pthread（POSIX）と CreateThread（Windows）の切り替え |

⚠️ **`runtime/core.c` には入れません。** ベアメタルには OS のスレッドがありません。
`time` と同じ扱い（[ベアメタルで使えないモジュール](../../lib/README.md)）にします。

⚠️ **2 実装の一致**（`src/` と `selfhost/`）は当然守ります。

### 3.1 ランタイムとの ABI（実装で決めたこと）

**`i64` を 2 つ取って `i64` を返す関数、の 1 種類だけ**にしました。
1 つ目が呼ぶ相手の関数ポインタ、2 つ目がその引数です。

```
  spawn(work, 1000)
      ↓ codegen
  %f = ptrtoint ptr @work to i64
  %t = call ptr @pl_thread_spawn(ptr @pl.thunk.0, i64 %f, i64 1000)
```

`@pl.thunk.0` は codegen が**シグネチャごとに 1 つ**出す中継関数で、
`i64` を本来の型に戻して呼び、戻り値を `i64` に詰め直します。

🤔 **なぜ「全部 i64 として直接呼ぶ」ではいけないのか。**
**呼び出し規約は型で決まる**からです。`float` は整数と**別のレジスタ**で
渡され、`None` を返す関数には**戻り値レジスタがありません**。型を偽って
呼ぶと、その 2 つで静かに壊れます。**型どおりに呼ぶ場所を thunk 1 か所に
閉じ込め、ランタイムは型を 1 つも知らない**、という分け方にしました。

## 5. これが入ると何が言えるようになるか

**「注釈なしで Rust の `Send` に相当する保証」**です。

Rust は `Send` / `Sync` というトレイトを型に付けて回します。本言語は
**所有権の検査がすでに持っている情報だけ**で同じ判定ができます
（借りか、所有か、`rc` か）。利用者が書くものは増えません。

⚠️ 逆に言うと、**所有権検査が警告どまりなら、この保証も警告どまり**です。

**✅ 所有権検査は 0.18.0 から既定でエラーです**（A-24）。さらに、
`--warn-own` で警告へ落としたときも、**`spawn` を使ったファイルだけは
落ちません**（`E-MOVE-*` / `E-BORROW-*` / `E-MUT-*` がエラーのまま）。
逃げ道は逃げ道として要りますが、並行実行のところだけは通しません。

## 6. `async` / `await` について

初版のこの文書は「関数の色が増えるから入れない」の一行で切っていました。
**分析として不完全でした。** async には家族が 2 つあり、色が付くのは片方だけです。

| 家族 | 例 | 色 | 必要なもの |
|---|---|---|---|
| **状態機械型**（`async def` + `await`） | Rust, Python, JS, C# | **付く** | クロージャ、`Future[T]`、codegen の状態機械変換、executor、**`Pin` 相当** |
| **多重化型**（軽量スレッド） | Go, Java 21 の仮想スレッド, Erlang | **付かない** | M:N スケジューラ、伸びるスタック、syscall の差し替え |

**「現代の言語は非同期が書ける」は本当です。ただし Go と Java 21 は
`await` を書かせずにそれを達成しました。** 「非同期が書ける」ことと
「`async`/`await` というキーワードがある」ことは別です。

### 6.1 状態機械型が本言語で厳しいのは、思想ではなく構造の問題です

1. **クロージャが無い。** `spawn` ですら「関数 + 引数 1 つ」に落としている
   （§1）くらいで、`async` の合成（`join!` / `select!`）はクロージャ前提です。
2. **`Pin` 相当が要る。** `await` をまたいで生きる借用は、中断中の future の
   中で**自己参照ポインタ**になります。future はムーブされうるので参照が
   壊れる。Rust が `Pin` という Rust でいちばん醜い型を入れたのは、まさに
   これを止めるためです。本言語にはこれを表す手段がなく、入れれば
   [§0 ①](../roadmap.md#①-書きやすさが下がるならその安全機能は入れない)
   に真正面から反します。
3. **codegen の状態機械変換**は、関数を `await` の位置で分割して構造体 +
   `poll` 関数に組み替える処理です。**codegen 史上いちばん大きい変更**に
   なり、2 実装で一致させる必要があります。

### 6.2 だから構文ではなく実装で取りに行きます

**`spawn` / `join` が利用者から見える API である限り、その下が OS スレッドか
軽量スレッドかは `runtime/hosted.c` の実装詳細です。**

```
いま:   spawn(f, x) → pl_thread_spawn → pthread_create        （1 本 = OS スレッド）
あとで: spawn(f, x) → pl_thread_spawn → M:N スケジューラに投入  （10 万本でも動く）
              ↑ 利用者のコードも型システムも 1 文字も変わらない
```

- `async` / `await` を**キーワードとして**入れる = **一方通行の扉**。
  色は伝染するので、後から外せません。
- `spawn` を入れる = **両方向の扉**。同じ「非同期が書ける」に、戻れる道で着きます。

⚠️ そして忘れてはいけないこと。**`async`/`await` は CPU コアを 1 つも増やしません**
（並行 ≠ 並列）。Rust の async が速いのは tokio の下にスレッドプールが
あるからです。数値計算に効くのは §7 のほうです。

## 7. scoped spawn（実装 ✅）

§4.1 の穴（読み取りの共有ができない）を、**型を 1 つも増やさずに**塞ぎました。

```python
def rows(a: list[float], b: list[float], n: int, r0: int, r1: int) -> list[float]:
    ...                       # ★ a と b は借り。写しを取らない

scope:
    ts: list[Thread[list[float]]] = []
    p: int = 0
    while p < cores:
        ts.append(spawn(rows, a, b, n, lo(p), hi(p)))
        p = p + 1
    for th in ts:
        parts.append(th.join())
# ← ここまでに全部 join されている
```

### 7.1 なぜ借りを渡してよくなるのか

**ブロックの出口で、そこで始めたスレッドを必ず全部 join するから**です。
すると「借りは呼び出しより長生きしない」という借用検査の不変条件が
**成り立ったまま**になります。⚠️ **規則を緩めたのではありません。**
規則の前提を実際に満たすようにした、という形です。

### 7.2 `scope` は予約語ではありません（柔らかい予約語）

`scope` は「範囲」を表すごく普通の名前で、**このコンパイラ自身が
`scope: rc[Scope] | None` というフィールドに使っています**。
予約語にすると既存のコードが壊れるので、**文脈で決めます**。

| 書いたもの | どう読むか |
|---|---|
| `scope:` の次が改行 | ブロック |
| `scope: rc[Scope] \| None` | 変数宣言（今までどおり） |

3 トークン先読みで完全に分かれるので、あいまいさは残りません
（Python の `match` / `case` と同じ扱い）。

### 7.3 出口が 1 つであることを検査します（`E-SCOPE-1`）

出口の join が飛ぶと根拠そのものが崩れるので、**途中から抜けることを
禁じます**。`return` / `raise` / ブロックを越える `break` / `continue`、
そして**捕まえていない「失敗しうる呼び出し」**が対象です。
（ブロックの中のループの中の `break` は問題ありません。外へ出ないためです。）

### 7.4 ⚠️ 可変借用は渡せません（`E-SEND-4`）

**`scope:` が保証するのは寿命だけです。** 同じ値への可変借用を 2 本の
スレッドが持てば、寿命が足りていてもデータ競合になります。そして
「配る先が重なっていないか」は、ループの中で `spawn` する形
（まさに並列化したい形）では静的に分かりません。

書き換えたいものは **`own` で渡して結果を `join` で受け取る**か、
**`mutex[T]` に入れて**ください。行列積なら「各スレッドが自分の行ブロックを
`own` で作って返す」形になります。

### 7.5 実装

| 変えたところ | 中身 |
|---|---|
| `parser` | 柔らかい予約語 `scope:`（3 トークン先読み） |
| `sema` | `E-SCOPE-1`（途中で抜けない） |
| `ownck` | `scope:` の中では `E-SEND-1` を出さない／`E-SEND-4` を足す |
| `codegen` | 入口で `pl_scope_begin`、出口で `pl_scope_end`。⚠️ **解放より先に**呼びます（スレッドがそのブロックの局所変数を借りていることがあるため） |
| `runtime/hosted.c` | スレッド局所の「枠」。`spawn` した Thread を記録し、枠を閉じるときに全部 join |

🤔 **なぜ枠（ランタイム側の記録）が要るのか。** 変数に入っているものだけを
join すれば足りる、とは言えません（`list[Thread[R]]` に貯めることがあるため）。
`spawn` した時点で記録しておくのが確実です。
⚠️ 枠はスレッドごとに別々です（`_Thread_local`）。`scope:` の中で始めた
スレッドが、さらにその中で `scope:` を開くことがあるためです。

### 7.6 効きめ（512×512 の行列積）

| | 0.13.1 | 0.13.2 |
|---|---|---|
| 1 コア | 316 ms | **45 ms** |
| 12 コア | 75 ms | **7 ms** |

1 コアが速くなったのは、**借りを共有できるようになって `a` と `b` の写しが
消えた**ことと、[ベクトル化](../roadmap.md#優先度-a-15c--添字の範囲をループの外で-1-回だけ確かめる実装済み-)が
効いたことの合わせ技です。
