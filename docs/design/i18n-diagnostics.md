# エラーメッセージを日本語と英語で切り替える設計

**日本語のエラーメッセージを第一に保ったまま、英語でも同じ質の診断を出せるようにします。**

> **現在地** — **段階 0 が 0.50.0、段階 1〜3 が 0.51.0、段階 4 が 0.52.0 で入り、すべての段階が終わりました。**
> コンパイラの診断（字句・構文・型・所有権・モジュール・コマンドライン、約 1100 文面）は、
> すべて `--lang=en` / `PLC_MSG_LANG=en` で英語になります。日本語の出力は 1 バイトも変わっていません
> （書き換えの前後で全試験の `--check` の出力を突き合わせて確かめました）。
> 実行時のエラーと標準ライブラリの panic も、**動かしたときの** `PLC_MSG_LANG` で日本語（既定）と英語を切り替えます（§10）。

> **前提**
>
> - **日本語が正本です。** 文面を決めるのも、試験が見るのも、既定で出るのも日本語です。
>   英語は「日本語の訳」で、日本語の文面を変えたら英語も追いかけます（逆はありません）。
> - **言語仕様は 1 つも変えません。** 変わるのはコンパイラが出す文字列だけです。
> - **「clang だけで建つ」を守ります。** gettext などの外部の道具は使いません。
> - **2 つの実装（C 版とセルフホスト版）は、どちらの言語でも 1 文字違わない診断を出します。**

## 3. 鍵

### 3.1 呼び出しの形

いまの書き方：

```c
// C 版
error_at_hint(n->tok, "本言語には暗黙の型変換がありません（言語仕様 3.5）",
              "型 '%s' と '%s' に演算子 '%s' は適用できません", l, r, op);
```

これからの書き方：

```c
// C 版
Diag d = {0};
d.code    = "E-TYPE-3";
d.message = msg("E-TYPE-3", "型 '{0}' と '{1}' に演算子 '{2}' は適用できません", l, r, op);
d.primary = (DiagLabel){tok, msg("E-TYPE-3.label", "この演算子の両辺の型が違います")};
d.hint    = msg("E-TYPE-3.hint", "本言語には暗黙の型変換がありません（言語仕様 3.5）");
diag_fail(&d);
```

```python
# セルフホスト版（同じ鍵・同じ日本語）
m: str = diag.msg("E-TYPE-3", "型 '{0}' と '{1}' に演算子 '{2}' は適用できません", [l, r, op])
```

- `msg(鍵, 日本語, 差し込み...)` は、**日本語のときは第 2 引数をそのまま**、英語のときは表を鍵で引いた
  文面を使い、差し込みを埋めて返します
- **日本語はいままでどおりコードの中に書きます。** 読む人がその場で文面を見られて、
  直すのも 1 か所です（英語の表は `make check-msgs` が追いかけさせます）
- 1 つの診断の中の「主メッセージ・ラベル・ヒント・関連する位置の見出し」は、
  鍵の後ろに `.label` / `.hint` / `.note` を付けて区別します

### 3.2 鍵は診断コードにする（→ 段階 1〜3 で見直し：§3.3）

鍵は**診断コードそのもの**にします。いまコードを持たない約 670 か所にも、コードを振ります。

| 分類 | 例 | 振る範囲 |
|---|---|---|
| 字句 | `E-LEX-1` | lexer |
| 構文 | `E-SYNTAX-12` | parser |
| 型 | `E-TYPE-3` | sema |
| 名前 | `E-NAME-2` | 未定義・重複 |
| モジュール | `E-MOD-4` | import |
| 既存のもの | `E-MOVE-1` `E-BORROW-9` `E-RAISE-1` `E-EXPORT-3` `E-DROP-2` … | **番号は変えない** |

★ **コードを付けるのは、英語のためだけではありません。** 日本語の利用者が英語の記事を探すとき、
英語の利用者が日本語の記事を見つけたとき、**コードで検索すれば同じ規則にたどり着けます**
（rustc の `E0308` と同じ考え方）。翻訳しても、規則の名前は 1 つのままです。

注意: 振った番号は**変えません**（削除したら欠番にします）。仕様書・記事・利用者のメモが番号を指すためです。

注意: 文面の中身で分岐する診断（「分岐によっては〜」が付くかどうか、など）は、
**分岐ごとに別の鍵**にします（`E-BORROW-9` と `E-BORROW-9.maybe`）。英語では語順が
変わるので、日本語の「前に付け足す」書き方が使えないためです。

### 3.3 実際に入れた形：鍵は内部の名前、コードは見える 29 種類のまま

段階 1〜3 では、§3.2 のとおり全部に新しいコードを振るのは**やめました。**

- 新しいコードを振ると、**見える出力が変わります**（`error[E-TYPE-3]: …` が増える）。
  「日本語の出力を 1 バイトも変えない」と両立しません
- 振った番号は変えられない約束（§3.2）なので、**約 1100 か所の番号を一度に決め切る**ことになります。
  規則ごとにまとめる作業は、診断の文面を見直すときに 1 つずつ行うほうが確かです

そこで、**鍵は表を引くためだけの内部の名前**にしました。利用者には見えません。

| 鍵 | どこの文面か |
|---|---|
| `lex.NNN` `parse.NNN` `sema.NNN` `own.NNN` `mod.NNN` `cli.NNN` `diag.*` | 2 つの実装で共通（C 版には必ずある） |
| `slexer.NNN` `sparser.NNN` `ssema.NNN` `sownck.NNN` `smodule.NNN` `smain.NNN` | セルフホスト版だけ（内部の誤り・`--help` の行など） |

- 見えるコード（`E-MOVE-1` `E-BORROW-9` `E-EXPORT-1` … の 29 種類）は**そのまま**です。
  英語でも同じコードが付くので、検索で同じ規則にたどり着ける点（§3.2 の★）は保たれます
- 鍵の番号は内部のものなので、文面を消したら欠番にするだけで、利用者との約束にはなりません
- C 版の静的な表（リストのメソッドの使い方など）は `MSGK("鍵", "日本語")` で鍵と日本語の組を持ち、
  使う所で `msgv()` で引きます

注意: 文面の部品（「分岐によっては、」「関数」「戻り値」など）は、それ自体を鍵で引いて差し込みます。
英語では部品の側に空白や語順を持たせます（`own.096` は ` on some branches` のように先頭に空白）。
**部品を比べて分岐してはいけません**（訳すと比べ先と一致しなくなる）。比べるときは同じ鍵で引いた文字列と比べます
（`check_export_type` の「戻り値」がその例です）。

## 4. 差し込み

日本語と英語では語順が違います。

```
ja:  型 '{0}' と '{1}' に演算子 '{2}' は適用できません
en:  operator '{2}' cannot be applied to types '{0}' and '{1}'
```

- `printf` の `%s` は**並び順に**埋めるので、英語で順番を入れ替えられません。
  そこで **`{0}` `{1}` …の番号つき**にします（中身は常に文字列。数は呼ぶ側で `str()` してから渡す）
- `{{` と `}}` は波括弧そのもの（f-string と同じ）
- 日本語も同じ `{0}` の書き方にそろえます（2 つの言語で同じ整形の関数を通すため）

注意: **差し込む値（型名・変数名・ソースの断片）は訳しません。** 利用者が書いたものだからです。

## 5. 英語の表

### 5.1 置き場所と形

```
yashirolang/msgs/en.tsv          （リポジトリ）
<PREFIX>/lib/plc/msgs/en.tsv     （make install で入る）
```

1 行 1 項目、タブ区切りで **鍵・英語・日本語（控え）** の 3 列です。
3 列目は訳す人がその場で原文を見るための写しで、コンパイラは読みません
（ソースの日本語と食い違えば `make check-msgs` が止めます）。
エスケープは `\n` `\t` `\\` の 3 つだけです（`"` はそのまま書きます）。

```
# 鍵	英語	日本語（控え）  ← 下は §3.2 の当初案の例。実際の鍵は §3.3
E-TYPE-3	operator '{2}' cannot be applied to types '{0}' and '{1}'
E-TYPE-3.label	the two sides of this operator have different types
E-TYPE-3.hint	there are no implicit conversions (language spec 3.5)
E-BORROW-9	'{0}' borrows '{1}', which may have been freed
E-BORROW-9.maybe	'{0}' borrows '{1}', which may have been freed on some paths
```

| 案 | 判断 |
|---|---|
| **TSV を実行時に読む** | **採用。** 2 つの実装が同じファイルを同じ規則で読めば、出力は必ず一致します。英語を直すのにコンパイラを建て直さなくて済みます |
| C のソースに埋め込む（生成） | 生成の道具が要ります（awk でも書けますが、セルフホスト版にも同じものを生成することになる） |
| JSON | 読むコードが大きくなります。TSV ならどちらの実装でも 20 行で読めます |

★ 表を読むのは**英語を選んだときだけ**です。日本語（既定）のときはファイルを開きません。
いまの動き・速さ・「ファイルが無くても動く」は変わりません。

### 5.2 表が無い・鍵が無いとき

| 状況 | 動き |
|---|---|
| 英語を選んだが `en.tsv` が見つからない | **日本語で出す**。最初の 1 回だけ `note: English messages not found; showing Japanese` |
| 鍵が表に無い（訳し忘れ） | **その診断だけ日本語で出す**（`make check-msgs` が CI で止めるので、配布物では起きない） |
| 差し込みの番号が合わない（`{3}` が無い） | `{3}` をそのまま残す（落とさない。診断を出すところで止まるのは本末転倒） |

★ **診断を出せなくなることは決してありません。** 英語の表は「あれば使う」ものです。

## 6. 切り替え方

### 6.1 選び方（強いものが勝つ）

| 優先 | 書き方 | 用途 |
|---|---|---|
| 1 | `yashirolang --lang=en prog.ys` | その 1 回だけ |
| 2 | `PLC_MSG_LANG=en` | シェル・CI・エディタの設定 |
| 3 | （何も無い） | **日本語** |

`--lang` / `PLC_MSG_LANG` に書けるのは `ja` / `en` / `auto` です。
`auto` は `LC_ALL` → `LC_MESSAGES` → `LANG` の順に見て、`ja` で始まれば日本語、それ以外は英語にします。

### 6.2 なぜ既定を日本語に固定するのか

| 案 | 判断 |
|---|---|
| **既定は日本語。ロケールに合わせるのは `auto` を選んだときだけ** | **採用。** 同じコマンドが、どの機械でも同じ文面を出します |
| 既定をロケールに合わせる | ✗ Linux の CI（`LANG=C.UTF-8`）で黙って英語になり、日本語の文面を見ている試験が**場所によって**落ちます。「手元では通るのに CI で落ちる」は、このリポジトリが何度も踏んだ形です |

英語圏の利用者には、README の最初に `export PLC_MSG_LANG=auto`（または `en`）を案内します。
**`ysm`・エディタ拡張・IDE は `PLC_MSG_LANG` をそのまま受け継ぐ**ので、1 か所の設定で揃います。

## 7. 枠の言葉

診断の枠（`src/diag.c` / `selfhost/diag.ys`）も、同じ表で切り替えます。

| いま | 日本語 | 英語 |
|---|---|---|
| `error` / `warning` | （そのまま） | （そのまま） |
| `note:` | （そのまま） | （そのまま） |
| `= ヒント:` | `= ヒント:` | `= help:` |
| `関連する位置` | `関連する位置` | `related location` |

注意: `error[E-MOVE-1]:` の形は**どちらの言語でも同じ**にします。エディタ拡張・IDE・試験が
この形で診断を拾っているためです（コードと位置で拾い、文面には依存させない）。

## 8. 抜けを止める（`make check-msgs`）

`tools/check_msgs.sh`（sh と awk だけ。「clang だけで建つ」の範囲）で次を確かめ、CI に入れます。

| 確かめること | 例 |
|---|---|
| ソースの全部の鍵が `en.tsv` にある | `E-TYPE-3` を足したのに訳していない |
| `en.tsv` にあってソースに無い鍵が無い | 消した診断の訳が残っている |
| **日本語と英語で差し込みの番号の集合が同じ** | 日本語は `{0}{1}{2}`、英語は `{0}{1}`（1 つ落ちている） |
| C 版とセルフホスト版で、同じ鍵の日本語が同じ | 片方だけ直した |
| 同じ鍵が 2 つの違う日本語で使われていない | 鍵の書き写し間違い |
| `en.tsv` の 3 列目（日本語の控え）がソースと同じ | 日本語を直したのに英語を見直していない |
| 鍵の置き場所（`s` で始まる区分はセルフホスト版だけ、それ以外は C 版に必ずある） | 片方の実装にしか無い文面 |
| `en.tsv` に同じ鍵が 2 行無い | 足すときの書き間違い |

★ 最後の 2 つは、**いまは `tests/selfhost.sh` が出力を突き合わせて間接的に見ている**ことを、
ソースの段階で直接見られるようにするものです。

## 10. 実行時のエラーと標準ライブラリ（段階 4）

作ったプログラムが出すエラー（`runtime error: …`）は、**コンパイラの利用者ではなく
プログラムの利用者**が読みます。そのため、決め方を分けます。

| | 決め方（0.52.0） |
|---|---|
| 実行時のエラー（`runtime/`） | **既定は日本語**。**プログラムを動かしたときの `PLC_MSG_LANG`**（`ja` / `en` / `auto`）で英語にできる（コンパイルしたときではない） |
| 表 | `runtime/core.c` と `runtime/hosted.c` の中に、**日本語と英語の両方を C の文字列で**持つ（ファイルを読まない。ベアメタルにはファイルが無いため） |
| 言語を決める所 | `core.c` の変数 `pl_rt_lang`（1 = 日本語、0 = 英語）。PC の上では `hosted.c` が**読み込まれたとき**（constructor）に `PLC_MSG_LANG` を見て決める。実行ファイルでも、Python から読み込む共有ライブラリでも同じに動く |
| ベアメタル（`core.c` のみ） | 誰も `pl_rt_lang` を書かないので**英語**（いまと同じ）。新しいフックは求めない |
| 枠の言葉 `runtime error:` | **言語によらず同じ**（コンパイラの `error:` と同じ考え方） |
| `panic(...)` に利用者が渡した文面 | **訳さない**（利用者のものだから） |
| 標準ライブラリの panic | `lib/i18n` の `pick(日本語, 英語)` を通して出す。利用者のプログラムも使える |
| 標準ライブラリの raise の `message` | **日本語のまま**（言語によらず同じ）。`message` は値なので、訳すと文面で分岐していた利用者のコードが言語で動きを変えてしまう |

★ 契約違反の文面は、コンパイラが `requires of divide (line 2)` の形で IR に置きます（言語によらず同じ IR）。
日本語のときはランタイムが `divide の requires（2 行目）` に並べ替えます。

★ スタックの使い切り（`stack overflow`）はシグナルの中で知らせるので、そこでは `getenv` を呼びません。
読み込みのときに決めた `pl_rt_lang` を見て、用意しておいた 2 つの文字列のどちらかを書くだけです。

注意: 英語の時代の文面（`index out of range: 5 (3)` など）は、`PLC_MSG_LANG=en` で動かすと
**以前とまったく同じ**に出ます。英語の文面を読んでいたスクリプトは、`PLC_MSG_LANG=en` を付ければ動きます。

試験は `# RUN-LANG: en`（動かすときの言語）と `# STDERR:`（実行時の標準エラーに含む文字列）で書きます
（`rt_msg_*` / `lib_i18n*`）。

## 11. 機械可読な出力（A-36）との関係

ロードマップの「診断を JSON で出す」（A-36）を入れるときは、**コードと差し込みの値を別々に**出します。

```json
{"code": "E-TYPE-3", "severity": "error", "file": "a.ys", "line": 4, "col": 13,
 "args": ["int", "float", "+"], "message": "型 'int' と 'float' に演算子 '+' は適用できません"}
```

エディタ拡張（`yashirolang-vscode`）は、`code` と `args` があれば**自分で好きな言語に訳せます**。
この設計の鍵（＝コード）と差し込み（`{n}`）は、そのまま JSON に載る形にしてあります。

## 12. 決めたこと・決めていないこと

| 問い | 決定 |
|---|---|
| 実行時のエラーの既定の言語 | **日本語にそろえる**（0.52.0 で実施。英語は `PLC_MSG_LANG=en` で） |
| 標準ライブラリの raise の `message` | **日本語のまま**（§10。値なので訳さない） |
| 英語の文面の文体 | **rustc に近い短い文**（小文字で始めて、句点を付けない） |
| `auto` を既定にする日が来るか | 決めていない。CI と試験がすべて `PLC_MSG_LANG` を明示するようになれば、検討できる |
| 英語以外（中国語・韓国語など） | 決めていない。仕組みは `msgs/<言語>.tsv` を足すだけで済む形にしてある |
