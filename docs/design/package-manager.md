# パッケージマネージャ

`ysm` は yashirolang のパッケージマネージャです。**レジストリを運営しません。**
依存は git のリポジトリを直に指し、「一度公開した版は変わらない」という
保証は中央のサーバではなく利用者の手元の `package.lock` が持ちます。

```bash
ysm init myapp
ysm add json https://github.com/user/json-pkg 1.2.0
ysm build
```

---

## 1. なぜレジストリを作らないのか

パッケージレジストリは、**個人が運営するには荷が重い設備**です。落ちれば
全利用者のビルドが止まり、乗っ取られれば全利用者に任意のコードが配られ、
名前は先着順なので typosquatting の的にもなります。しかも一度動かしたら
止められません。

一方、レジストリが果たしている仕事は、実は 3 つに分けられます。

| 仕事 | 誰がやるか（従来） | この設計では |
|---|---|---|
| ① 名前から在り処を引く | レジストリ | **git の URL がそのまま在り処**（インデックス不要） |
| ② 成果物を配る | レジストリの CDN | **git のホスティング**（GitHub など） |
| ③ 「この版はこの中身」を保証する | レジストリの不変性 | **`package.lock`**（commit と tree の SHA） |

①②は他人の設備をそのまま使えます。③だけが本質で、それは
**利用者のリポジトリに入る 1 つのファイル**で足ります。運営する設備は
ゼロになります。

これは Go modules（中央レジストリを持たず、import パスがリポジトリを指し、
`go.sum` が内容ハッシュを持つ）や Zig（`build.zig.zon` に URL とハッシュ）と
同じ選択です。cargo と pip も git 依存を扱えますが、既定はレジストリです。

### 他の言語との比較

| | pip / PyPI | cargo / crates.io | go modules | **ysm** |
|---|---|---|---|---|
| 中央レジストリ | 必須 | 既定 | **無し**（proxy は単なるキャッシュ） | **無し** |
| 版の指定 | 範囲（`>=1.2,<2`） | semver 範囲（`^1.2`） | 下限のみ | **下限のみ** |
| 解決 | 後戻り探索 | ソルバ（互換範囲の最大） | MVS | **MVS** |
| ロック | 標準に無かった（PEP 751 で追加） | `Cargo.lock`（標準） | `go.sum`（標準） | **`package.lock`（標準）** |
| 同じ名前の複数版の同居 | できない | **できる**（記号にハッシュ） | できない（major 違いは別名） | **できない**（§5） |
| インストール時のコード実行 | **あり**（sdist の `setup.py`） | **あり**（`build.rs` / 手続きマクロ） | 無し | **無し**（§6） |

## 2. 全体像

```
myapp/
  main.ys            自分のコード
  package.pkg       宣言（人が書く。git に入れる）
  package.lock      確定（ysm が書く。git に入れる）
  deps/              展開先（ysm のもの。sync のたびに作り直す）
    json.ys
    json_lex.ys
    httpx.ys
```

```bash
yashirolang -I deps main.ys -o myapp     # ysm build がこれを実行します
```

**コンパイラに足した機能は `-I <dir>` だけです。**
パッケージ管理の全部は `ysm` という別のプログラムに閉じていて、
言語にもコンパイラにも「パッケージ」という概念はありません。

---

## 3. 宣言 — `package.pkg`

```
name    myapp
version 0.1.0
entry   main.ys
src     .

dep     json  https://github.com/user/json-pkg  1.2.0
dep     httpx https://github.com/v/httpx-pkg    0.3.0
```

| 項目 | 意味 |
|---|---|
| `name` | パッケージ名（識別子）。取ってきた側は、これが依存名と一致しなければ受け取りません |
| `version` | このパッケージの版。**タグ `v1.2.3` と一致していなければエラー**です |
| `entry` | `ysm build` が渡す入口ファイル（ライブラリなら省略） |
| `src` | `.ys` を置いてあるディレクトリ（既定 `.`） |
| `dep` | `dep <名前> <git の URL> <最低版>` |

`dep` の版は**下限だけ**です。上限は書けません（§5）。

---

## 4. 確定 — `package.lock`

```
lock 1
root httpx https://github.com/v/httpx-pkg 0.3.0
pkg  httpx https://github.com/v/httpx-pkg 0.3.0 d5997f84…0eb 14cf67f1…7b8
mod  httpx
pkg  json  https://github.com/user/json-pkg 1.2.0 5cbedf46…696 da4011f3…b9b
mod  json json_lex
```

**このファイルがこの設計の中心です。** 記録するのは:

- **タグではなく commit の SHA。** タグは張り替えられますが、commit の
  SHA は中身が 1 バイト変われば必ず変わります。取得はいつも SHA で行うので、
  タグを差し替えられても入ってくるのは前と同じ中身です。
- **tree の SHA も別に。** 取ってくるたびに突き合わせ、違えば止めます。
- **出てくるモジュール名。** 衝突をコンパイル前に見つけるためです。
- **`root` 行 — この宣言から解決した、という記録。** `package.pkg` の `dep`
  と食い違ったらロックは古いので解決し直します。「下限を満たしているか」で
  判断すると、依存を**消した**ときに気づけず、消したはずのものが入り続けます。

行指向なのは、**人が読めて、レビューで差分が意味を持つ**ようにするためです。
「json が 1.1.0 → 1.2.0 に上がり、SHA がこう変わった」が 2 行で見えます。

## 5. 版の決め方 — MVS

採っているのは Go と同じ **MVS（Minimal Version Selection）** です。

> ある名前に対して要求された**下限のうち、いちばん大きいもの**を選ぶ。

探索も後戻りもありません。理由は 3 つ:

1. **同じパッケージの 2 つの版を同居させられないから。** この言語では
   モジュール名が IR の名前修飾そのものです（`lexer.make`）。`json` の
   1.x と 2.x を同時にリンクすることは原理的にできません。cargo は記号に
   ハッシュを混ぜてこれを可能にしていますが、yashirolang にその仕組みは
   ありません。解の自由度が無い以上、ソルバを持つ意味がありません。
2. **勝手に上がらないから。** 誰かが宣言を書き換えない限り、選ばれる版は
   動きません。ロックが無くても結果が再現します。
3. **説明できるから。** 「なぜこの版か」が「誰がこの下限を要求したか」で
   一意に答えられます。

間接の依存を上げたいときは、それを**自分の宣言に直接書きます**
（`ysm update json` が自動でそうします）。MVS では「上げる」とは
「下限の要求を書き換える」ことだからです。

## 6. 安全性

レジストリを持たないぶん、守り方は取得のしかたそのものに埋め込みます。

### ① インストールでコードを実行しない

**これが最も大事な性質です。** `ysm` は作業ツリーを一切作りません。
`git clone --bare` したうえで、`git rev-parse` / `git show` / `git ls-tree` だけで中身を読みます。
その結果:

- フック（`.git/hooks`）が走らない
- サブモジュールが引かれない
- シンボリックリンクが作られない（`ls-tree` の mode `120000` を捨てる）
- `.ys` 以外のファイルは持ち込まない

npm の `postinstall`、pip の `setup.py`、cargo の `build.rs` に相当する穴が
**最初から存在しません**。この性質は後から取り戻せないので、最初に決めました。

⚠️ 逆に言えば、`ysm` は「ビルド前に何かを生成する」機能を持てません。
これは意図した制限です。

### ② 取得は SHA で、検証は tree で

| 攻撃 | 何が起きるか |
|---|---|
| タグを別の commit に張り替える | ロックの SHA で取るので**影響しません** |
| 履歴を書き換えてロックの commit を消す | 取得に失敗し、`履歴が書き換えられたか、URL が変わっています` で止まります |
| リポジトリの中身を差し替える | tree の SHA が合わず止まります |
| `deps/` を手で書き換える | `ysm verify` が見つけます（中身を git と 1 バイトずつ比べます） |

### ③ 外から来た文字列を検査してから使う

- git の呼び出しは `vcs.git()` を必ず通し、`protocol.ext.allow=never`
  （任意コマンドを起動できる転送方式）を殺し、フックの場所を空にします。
- シェルに渡す語は `shell.q()` で必ず包みます。
- パッケージ名・モジュール名は**識別子であることを確かめてから**使います。
  取ってきたファイル名がそのまま `import` の名前になるからです。
- 消す操作は `shell.run_rm()` に 1 つだけあり、`..` を含むパスを断ります。

### ④ 残っている弱いところ（正直に）

- **git の SHA-1。** 現在の git は SHA-1（衝突耐性が弱い）を使います。
  git が SHA-256 に移れば自動で強くなりますが、いまはそこが上限です。
- **TOFU。** 最初に取ってくるときの相手は検証していません。URL を信じる
  ところから始まります（署名タグの検証は将来の宿題）。
- **リポジトリの消滅。** 作者が消したら取れなくなります。`~/.cache/plc`
  に残りますが、これは対策としては弱く、ベンダリング（`deps/` ごと
  コミットする）が確実です。
- ~~**名前の重複。**~~ ✅ **A-32 で解けました。** モジュールは
  `deps/<パッケージ名>/<モジュール>.ys` に入り、名前は `pkg.mod` になります。
  2 人が同じモジュール名を出しても、標準ライブラリと同じ名前でも、ぶつかりません。
  ⚠️ 残るのは「自分のファイルと同じ名前」だけで、これは `ysm` が止めます。

## 7. 名前空間について（✅ A-32 で入りました）

**かつて**：`import x` は「`x.ys` を 1 つ読む」だけで、モジュール名は
プログラム全体で一意でした。⚠️ **実際に踏みました** — 標準ライブラリに
`lib/json.ys` を足した瞬間、`json` という名前のパッケージが使えなく
なりました。`ysm` は `yashirolang --print-lib-dir` に訊いて**入れる前に**断って
いましたが、これは検出であって予防ではありません。

**いま**：`import pkg.mod` が `pkg/mod.ys` を読みます。`ysm` は
**`deps/<パッケージ名>/<モジュール>.ys`** に展開するので、一般名の
パッケージも、同じモジュール名を出す 2 つのパッケージも入ります。

```python
import shadow.json     # deps/shadow/json.ys
import json            # 標準ライブラリ
```

★ 探索の仕組みは**変えていません**。`src/module.c` は名前のドットを
ディレクトリの区切りに読み替えるだけで、探す場所の集合は今までどおりです
（入口のディレクトリ → `-I` → 標準ライブラリ）。

⚠️ 別名（`as`）・`from x import y`・相対 import は入れません。どれも
「この名前はどこから来たのか」をソースから消すためです
（[版の記録 0.23.0](../changelog.md)）。

## 8. コンパイラ側の変更

`-I <dir>` の 1 つだけです（`src/module.c` / `selfhost/module.ys`）。

- 探す場所は ①入口のディレクトリ ②`-I` で足した場所 ③`lib/` になりました。
- **優先順位は決めません。** 2 つ以上で見つかったらエラーです（14.4 節の
  方針をそのまま広げました）。曖昧さは解決規則を作るより起こせなくするほうが
  小さく済みます。
- 見つからないときの診断は、探した場所を全部並べます。

```
error: モジュール 'greet' が複数の探索場所にあります
   = ヒント: 見つかった場所:
             app/greet.ys
             deps/greet.ys
             どちらかの名前を変えてください
```

## 9. 将来やるかもしれないこと

| こと | 状態 |
|---|---|
| 署名タグの検証（`git verify-commit`） | 個人運営でも入れられる。次の候補 |
| `ysm vendor`（`deps/` をコミットする形） | いまも `deps/` をコミットすれば動く。明示的な指令があると親切 |
| `--offline` | キャッシュだけで動かす |
| **名前 → URL の索引**（欲しくなったら） | **成果物はホストしない**索引だけのリポジトリを GitHub Pages で配る。守るべきサーバがゼロ（Homebrew の tap や AUR と同じ形）。ロックが SHA を持つ限り、索引は別名解決の便利機能に留まる |
| プレリリース版（`1.0.0-rc1`） | いまは受け付けない |
