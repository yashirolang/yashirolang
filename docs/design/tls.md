# TLS の設計

**なぜ暗号を自分で書かなかったのか、なぜ既定のビルドに入れないのか。**
使い方は [reference/net.md](../reference/net.md) 2.5 節にあります。

> **前提** — この文書が説明するのは `lib/tls.ys` と `runtime/tls.c` の
> 2 つだけです。言語には**手を入れていません**（`enum` も `match` も
> 増えていません）。「ライブラリは言語を 1 行も変えずに足せる」という
> [roadmap](../roadmap.md) の主張が、ここでも成り立っています。

---

## 1. 決めたこと

| | |
|---|---|
| 採った | **OpenSSL 3.x に任せる**（リンクするだけ。ソースは取り込みません） |
| 採った | **既定のビルドには入れない**（`make TLS=1` で入ります） |
| 採った | 入っていないときは**はっきり断る**（黙って平文に落ちません） |
| 採った | 検証・名前の照合・最低版を**利用者が下げられない**ようにする |
| ✗ 捨てた | TLS を yashirolang で自前実装する |
| ✗ 捨てた | mbedTLS などを `third_party/` に取り込む（vendoring） |
| ✗ 捨てた | `insecure_skip_verify` に相当する逃げ道 |
| ✗ 捨てた | 相互 TLS（客にも証明書を求める）。要るようになってから |

---

## 2. なぜ自前で書かないのか

この言語は「安全な言語仕様」を看板にしています。そこで TLS 1.3 の
ハンドシェイク・X.509 の連鎖検証・定数時間の比較を**新しく書く**と、
**看板の下でいちばん危ない部分だけが未検証**という状態になります。

| 自前で書くと背負うもの | |
|---|---|
| 暗号そのもの | 定数時間の実装。書き方が少しずれるだけで鍵が漏れます |
| X.509 | ワイルドカード・NUL 入りの名前・連鎖の長さ・失効。穴の博物館です |
| 追従 | 新しい攻撃が出るたびに、こちらが直す番になります |

**得るものは「依存が減ること」だけ**で、払うものが釣り合いません。
ここは車輪を再発明しない所だと判断しました。

注意: **これは「自分で書けない」という話ではありません。** `json` も
`decimal` も `fft` も自前です。違いは、**間違えたときに誰が損をするか**
です。`fft` の誤りは結果が狂うだけですが、TLS の誤りは**利用者の合言葉が
漏れます**。

## 3. なぜ OpenSSL 3.x なのか

| 候補 | ライセンス | 判断 |
|---|---|---|
| **OpenSSL 3.x** | Apache-2.0 | **採用。** このリポジトリと同じライセンスで、摩擦がありません |
| OpenSSL 1.1.1 以前 | 旧 OpenSSL/SSLeay | ✗ 宣伝条項があり Apache-2.0 と両立しません |
| LibreSSL | ISC ＋ 旧 OpenSSL | API は近いものの、ライセンスが混ざります |
| mbedTLS | Apache-2.0 | ✗ 取り込むなら CVE の追従が**こちらの仕事**になります |
| BearSSL | MIT | ✗ 信頼する証明書を自分で用意する必要があり、層が厚くなります |
| GnuTLS | LGPL-2.1+ | ✗ 静的リンクの条件が面倒で、利用者に負担が回ります |

**★ 3.0 未満はビルドの時点で止めます**（`runtime/tls.c` の `#error`）。
技術的には動いてしまうので、気づかないまま両立しないライセンスの
ライブラリに繋がるほうが困ります。

**★ 取り込みません（リンクするだけ）。** OpenSSL のソースはこの
リポジトリに 1 行も入りません。配布物の中身は Apache-2.0 のままです。

それでも、**任意で何に繋がるのかは `NOTICE` に書いてあります**（義務では
ありませんが、受け取った人が自分で確かめられるべきだからです）。TLS を
有効にして**配る**人は、自分の配布物に OpenSSL が含まれるかを確かめて
ください——動的リンクなら含まれません。

注意: **`LICENSE` は 1 文字も変えていません。** 末尾の付録
（`Copyright [yyyy] [name of copyright owner]`）は「あなたの作品にこの許諾を
適用する方法」の**手引き**で、**ソースの先頭に貼る雛形**です。埋める空欄では
ありません。許諾の本文は逐語で配るものなので、著作権表示は `NOTICE` と
ソースの先頭に置いてあります。

## 4. なぜ既定で入れないのか

**「clang だけで建つ」という約束があるからです。** SMT ソルバを同梱
しないと決めたのと同じ理由です（[roadmap](../roadmap.md) §3）。

```
make            → 今までどおり。外のライブラリは要りません
make TLS=1      → pkg-config で openssl >= 3.0 を探して有効化
```

**★ どちらで建てても `runtime/tls.c` はコンパイルされます。** TLS なしの
ときは、同じ名前の関数が「TLS を組み込まずに建てました」と断る中身で
定義されます。おかげで、

- `import tls` しただけでリンクが落ちることがない
- `lib/tls.ys` に「TLS があるときだけ」の分岐が要らない
- **黙って平文に落ちることがない**

の 3 つが同時に成り立ちます。

注意: **配布物は TLS なしで作ります。** リンクに要る指定
（`-L/…/openssl@3/lib -lssl -lcrypto`）は**建てた機械の道**を
コンパイラに埋め込む形なので（`PLC_RUNTIME_LIBS`）、別の機械へ持っていくと
その道はありません。TLS が要る人は**自分の機械で `make TLS=1`** してください。
埋め込みは環境変数 `PLC_RUNTIME_LIBS` で上書きできます。

注意: **TLS の指定が変わったら建て直します。** make が見るのは時刻だけ
なので、判子（`build/tls.stamp`）を置いて中身の変化を見ています。
これが無いと `make` のあとの `make TLS=1` が素通りし、「有効にしたはずなのに
断られる」という分かりにくい形になります。

## 5. なぜ `Stream` という 1 つのクラスなのか

上の層（`http`）は「いま TLS か平文か」を気にせず読み書きしたい。
素直に書くならインタフェースですが、

> **`raises` するメソッドはインタフェースに宣言できません**
> （[generics-and-interfaces.md](generics-and-interfaces.md) §2）

という制限があり、`recv` は `raises net.NetError` です。そこで**多態では
なく 1 つのクラス**にして、中で分けました。

```python
class Stream:
    sock: net.Conn      # 下のソケット
    h: int              # TLS の手（**-1 なら平文**）
    on: bool            # まだ開いているか
```

| | |
|---|---|
| 利点 | `http` の読み書きが 1 本のまま。`http` と `https` で解釈が分岐しません |
| 利点 | 平文の道に暗号の分岐が入らない（`h < 0` で素通し） |
| 代償 | 「TLS の接続」という型が無い（`s.secure()` で訊きます） |
| 注意 | `on` は `h` で代用できません（**平文のときも `h` は -1**） |

**この制限が外れたら**（インタフェースが `raises` を扱えるように
なったら）、`Stream` はインタフェース 1 つと実装 2 つに割れます。
そのとき `http` 側は**書き換えずに済みます** — 呼んでいるメソッドの
名前と形が同じだからです。

## 6. なぜ検証を外す口を置かないのか

`insecure_skip_verify` の類は、**外した状態が本番に残る**のが定番の事故です。
この言語は範囲外アクセスの検査にも桁あふれの検査にも逃げ道を置いて
いません（[roadmap](../roadmap.md) §1）。同じ扱いにしました。

自己署名を試す道は**別に用意してあります**。「検証を外す」のではなく
**「何を信じるか」を指定します**。

```python
ctx: tls.Context = tls.client_context()
ctx.set_ca_file("my_ca.pem")
c: tls.Stream = tls.connect_with(ctx, "localhost", 8443)
```

**★ 名前の照合はそのまま効きます。** 上の証明書が `localhost` のものなら、
同じ相手に `127.0.0.1` として繋いでも断られます。`tests/tls.sh` が
まさにそれを確かめています。

## 7. なぜ手（ハンドル）が番号なのか

`SSL *` をそのまま `int` で返すと、でたらめな数を渡されたときに落ちます。
表に入れて**番号**を渡し、使うたびに確かめます。

```
手 ＝ 枠の番号 * 4096 + 世代
```

**★ 世代を混ぜます。** 枠は使い回すので、世代が無いと「閉じた接続の
番号」があとから開いた別の接続に当たります——**閉じたはずの相手に書く**、
という一番まずい取り違えです。

---

## 8. 試験

`tests/tls.sh` が自己署名の証明書をその場で作り、自分に繋ぎます。
**外には一切出ません。**

| 見ているもの | なぜ |
|---|---|
| 信頼する証明書を渡せば往復できる | 通ること |
| **知らない証明書は断る** | 検証が本当に効いているか |
| **名前が違えば断る** | 照合が本当に効いているか |
| **平文で待つ相手に TLS では繋がらない** | 落ちないこと |
| **TLS で待つ相手に http では繋がらない** | 落ちないこと・その客でサーバーが終わらないこと |

**★ 5 つのうち 4 つが「繋がらないこと」です。** 暗号化の層で大事なのは
「通ること」より「**通ってはいけないものが通らないこと**」だからです。

注意: **秘密鍵はリポジトリに入れません。** 走らせるたびに作って捨てます。
試験用と書いてあっても、鍵が版管理に入っていると、いつか本物として
使われます。

注意: TLS を組み込んでいないビルドでは**飛ばします**。失敗ではありません
——組み込まないことを選べるのが設計です。
