# 中身を持つ枝（A-41）の設計

> 0.30.0 で入れた `enum` は**名前だけの枝**です（表現は i64）。ここでは
> `Shape.Circle(r)` のように**中身を持つ枝**をどう足すかを決めます。
> 仕様は [spec/language-spec.md §3.4.7](../spec/language-spec.md)。

---

## 1. 何が要るのか

```python
enum Shape:
    Circle(r: float)
    Rect(w: float, h: float)
    Empty                      # 中身なしの枝も混ぜられる

match s:
    case Shape.Circle(r):      # ★ r が束縛される
        area = 3.14 * r * r
    case Shape.Rect(w, h):
        area = w * h
    case Shape.Empty:
        area = 0.0
```

構文木・`Result` 相当・状態機械の「状態ごとのデータ」が、クラスとインタフェースの
組み合わせではなく**型 1 つ**で書けるようになります。

---

## 2. 表現：枝ごとの隠しクラス ＋ 先頭のタグ

| 決めたこと | 中身 |
|---|---|
| 枝 1 つにつき**隠しクラス**を 1 つ作る | `Shape$Circle`（フィールド: `__tag: int`, `r: float`） |
| **タグは必ず先頭のフィールド** | どの枝でも同じ位置（オフセット 0）に i64 があります |
| 値の表現は**そのクラスへのポインタ** | 「値はどれも 8 バイト」の前提はそのまま |
| 中身なしの枝も**同じ形**（`__tag` だけのクラス） | 表現が枝ごとに変わると、代入も `match` も 2 通りになります |

**なぜ隠しクラスなのか。** レイアウト・確保・解放・フィールドの読み書きが、
**クラスのためにもう書いてあるもの**でそのまま動くからです。新しい種別を
作ると、所有権検査と解放の挿入をもう一度書くことになります
（0.30.0 の `match`、0.32.0 の `for`、0.33.0 の `lambda` と同じ方針です）。

**なぜタグを先頭に置くのか。** `match` は「どの枝か」を**中身を見る前に**
決めます。先頭に置けば、どの枝のポインタでも同じ場所を読めます
（LLVM のポインタは型を持たないので、見立て直しに命令は要りません）。

---

## 3. 脱糖

構文解析の時点で、枝ごとの隠しクラスを**トップレベルに持ち上げます**
（`lambda` と同じ手です）。

```python
enum Shape:                    class Shape$Circle:
    Circle(r: float)               __tag: int
    Rect(w: float, h: float)  →    r: float
                                   def init(self, __tag: int, r: float) -> None:
                                       self.__tag = __tag
                                       self.r = r
                               （Shape$Rect も同じ形）
```

- **生成** `Shape.Circle(1.5)` → `Shape$Circle(0, 1.5)`（第 1 引数がタグ）
- **場合分け** `case Shape.Circle(r):` → タグを比べ、当たったら中身を読む

```python
match s:                       __m.0: Shape = s          # 1 回だけ評価
    case Shape.Circle(r):  →   if tag(__m.0) == 0:
        BODY                       __v.0: Shape$Circle = __m.0   # 見立て（命令なし）
                                   r: float = __v.0.r
                                   BODY
```

足す仕組みは 2 つだけです。

| 足すもの | 中身 |
|---|---|
| `ND_ENUMTAG` | 「先頭の i64 を読む」式。codegen は load 1 つ |
| 見立ての印（`is_enum_view`） | 「enum の値を枝のクラスとして見る」宣言。型検査を 1 か所だけ緩めます |

---

## 4. 所有権

**中身を持つ enum の値は、クラスと同じ扱い**です（ヒープに置かれ、出口で解放）。

- `s: Shape = Shape.Circle(1.0)` は所有します
- 関数に渡すと既定は借用、しまうには `own` が要ります
- `match` の束縛（`case Shape.Circle(r)`）は**フィールドを読む**のと同じです。
  値型は写し、`str` などは借用になります

**注意: 名前だけの enum（0.30.0）は今までどおり i64 です。** 中身を持つ枝が
1 つでもあれば、その enum は**全体がポインタ表現**になります。混ぜると代入も
`match` も 2 通りになるためです。

---

## 5. 断るもの

| 形 | 断る理由 |
|---|---|
| 枝の数と `case` の中身の数が違う（`case Shape.Rect(w)`） | どのフィールドを束縛したいのか決まりません |
| 中身のある枝を `Shape.Circle` とだけ書く | 中身を捨てているのか、書き忘れたのか分かりません |
| 中身なしの枝に `()` を付ける | 表記を 1 つに保ちます |
| 束縛の名前が重なる（`case Shape.Rect(w, w)`） | 後の束縛が前を隠します |

網羅の検査（0.30.0）は**そのまま効きます**。枝を足したら、`match` の書き漏れは
今までどおりコンパイルエラーになります。

---

## 6. やらないこと

- **枝の入れ子パターン**（`case Shape.Circle(Point(x, y))`）。まずは 1 段だけです
- **ガード**（`case Shape.Circle(r) if r > 0:`）。`if` を本体に書けば済みます
- 名前つきの束縛（`case Shape.Circle(r = radius)`）
