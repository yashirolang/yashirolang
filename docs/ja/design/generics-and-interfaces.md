# ジェネリクス・インタフェース・演算子の設計

**入っている機能の「なぜその形なのか」**です。コンパイラに手を入れるときに読みます。
使い方は [tutorial.md](../tutorial.md) に、規則は [spec/type-system.md](../spec/type-system.md) にあります。

> **前提** — 2 つの実装（C 版 `src/` とセルフホスト版 `selfhost/`）に**同じものを入れ**、
> 同じ IR を出さなければなりません。片方だけ直すとセルフホストの検証が壊れます。
> 実装の重さを見積もるときは、常に**この 2 倍**で考えてください。

## 1. ジェネリクス（単相化）

```python
class Dict[K, V]:
    keys_: list[K]
    vals_: list[V]

d: dict.Dict[str, Symbol] = dict.Dict()
```

**設計どおり単相化**で入りました。`Dict[str, int]` と `Dict[str, Symbol]` は
**別々のクラス**になります。

### 実装のしかた — 新しいパスを作らなかった

当初は「意味解析の後に単相化パスを 1 つ足す」と書いていましたが、
**型参照を解決したときに、その場でクラスの AST を複製する**形にしました。
既存の `declare_class` / `declare_class_members` をそのまま呼べるので、
新しい仕組みが要りません。

| 段階 | やったこと |
|---|---|
| 型参照 `Dict[str, Symbol]` | テンプレートを引き、AST を複製して名前を `Dict$str$Symbol` に |
| 型引数 | **`Type` として**束縛する（名前解決を経由しない）ので、他モジュールで定義したクラスも渡せる |
| 本体の検査 | 待ち行列に入れて**後でまとめて**行う（検査中にさらに実体が増えるため、増えなくなるまで繰り返す） |
| コード生成 | テンプレートは出さず、実体だけを出す |

### 決めたこと / 捨てたこと

| | |
|---|---|
| 採った | 単相化。型引数は `[]`。推論は**左辺の型から**だけ |
| ✗ 捨てた | 型制約（`T: Comparable`）。`==` が使えるかは実体化してみるまで分からない |
| 採った（0.4.0） | ジェネリック**関数**（`def f[T]`）。注意: クラスと違い **実引数の型から**推論する |
| 注意 | 実体はテンプレートのモジュールに作る。使う側のモジュールではない |

## 2. インタフェース（vtable をオブジェクトの先頭に置く）

```python
interface Show:
    def show(self) -> str

class Point(Show, Sized):
    def show(self) -> str: ...

def print_all(xs: list[Show]) -> None:
    for x in xs:
        print(x.show())
```

### 設計を 1 つ変えました：ファットポインタをやめました

当初は「実体へのポインタ ＋ vtable へのポインタ」の **2 語**（ファット
ポインタ）を想定していました。実装に入って、これがこの処理系と噛み合わない
ことが分かりました。

**この処理系は「値はどれも 8 バイト」という前提で組まれています。**
list の要素も、クラスのフィールドも、引数も、戻り値もそうです。2 語にすると
その全部に手を入れることになります。

そこで **vtable へのポインタをオブジェクトの先頭に隠しフィールドとして
持たせる**方式にしました。

```llvm
%Point.type = type { ptr, i64, i64 }   ; 先頭が vtable への隠しフィールド
@vt.Point = private constant [2 x ptr] [ptr @Point.show, ptr @Point.size]
```

| | |
|---|---|
| 利点 | インタフェースの値が **ただのポインタ**（8 バイト）のまま |
| 利点 | クラス → インタフェースの変換が **何もしないで済む**（同じポインタ） |
| 代償 | インタフェースを実装するクラスは 8 バイト大きくなる |

### スロット番号はプログラム全体で一意にしました

1 つのクラスが複数のインタフェースを実装できるようにするためです。
インタフェースごとに 0 から番号を振ると、呼ぶ側（インタフェースしか
知らない）がどの表のどこを見ればよいか決められません。

```llvm
@vt.Label = private constant [2 x ptr] [ptr @Label.show, ptr null]
                                                          ^^^^^^^^
                                        Sized は実装していないので null
```

**注意: 代わりに表は疎になります。** インタフェースが増えると全クラスの表が
伸びるので、数が多くなったら別の方式（実行時に探して覚える）が要ります。

### 決めたこと / 捨てたこと

| | |
|---|---|
| 採った | インタフェース（振る舞いだけ）。**実装の継承は入れない** |
| 採った | 1 つのクラスが複数のインタフェースを実装できる |
| ✗ 捨てた | クラスの継承。フィールドのレイアウトが複雑になり、得るものが少ない |
| ✗ 捨てた | 既定実装つきメソッド |
| 採った | **`raises` するメソッドも宣言できる**（A-40。0.34.0）。投げうるエラーは**宣言で固定**し、実装に同じ `raises` を求めます |

#### `raises` をどう通したか（A-40）

`raises` 関数は**末尾にエラー出力引数が 1 本増える**だけです
（[error-handling.md §2](error-handling.md)）。vtable に入るのはその関数の
ポインタなので、**呼ぶ側が同じ段取りで呼べば通ります**——エラースロットを
最後の引数で渡し、戻ってタグを見る。呼び先が名前ではなくレジスタ（表から
読んだ値）なだけです。

そのため codegen の追加は「呼び出しを出すところを、呼び先を受け取る形に
一般化する」（`emit_call_to`）**1 か所だけ**でした。

**投げうるエラーは宣言で固定します。** 呼ぶ側はインタフェースの宣言しか
見ないので、実装ごとに違う `raises` を許すと、`try` を書く手がかりが
無くなります。実装が宣言と違えば断ります（`err_iface_raises_more` /
`err_iface_raises_less`）。

## 3. 関数型とクロージャ

### 入ったもの：関数型 `fn(A, B) -> C`

```python
def integrate(f: fn(float) -> float, a: float, b: float, n: int) -> float: ...

integrate(sq, 0.0, 1.0, 1000)
integrate(math.sin, 0.0, 3.0, 1000)     # 他モジュールの関数も渡せる
g: fn(float) -> float = math.cos        # 変数に入れられる
```

これで `lib/numeric.ys`（積分・求根・微分・ODE・最適化）と
`stats.sorted_by`（比較関数つきソート）が書けるようになりました。

**実装のしかた**

| パス | やったこと |
|---|---|
| 構文 | `fn` は **予約語にせず**、型の位置でだけ文脈的に認識（既存コードの `fn` という名前を壊さないため） |
| 型 | `TY_FN`（引数の型の並び + 戻り型） |
| 意味解析 | 変数に無い名前は関数を探し、`FuncSig` から関数型を作る。呼び出し側は「名前が関数型の変数なら間接呼び出し」 |
| コード生成 | 値は `@name` そのもの。呼び出しは箱から `ptr` で読んで `call` の呼び先に置くだけ |

**注意: LLVM では呼び先がラベルでもレジスタでも書き方が同じ**なので、
コード生成はほとんど何もしていません。難しかったのは意味解析側（名前解決の
順序）でした。

### 入っていないもの：クロージャ

外側の変数を捕まえる `|x| x + k` はまだありません。

### 優先度を下げました：インタフェースが代わりになります

「状態を持った関数」が要るなら、**状態をクラスに持たせてインタフェースで
渡せば済みます**（0.4.0 で確認）。

```python
interface Less:
    def less(self, a: float, b: float) -> bool

class ByDistance(Less):
    center: float                      # ← これが「捕まえた変数」
    def less(self, a: float, b: float) -> bool:
        ...self.center...

sort_by(xs, ByDistance(5.0))           # 5.0 に近い順
sort_by(xs, ByDistance(1.0))           # 1.0 に近い順
```

クロージャが本当に足すのは **書き味だけ**（その場に書ける短さ）です。
表現できることは増えません。

しかも実装には無視できない問題があります。

| | |
|---|---|
| 表現 | `{関数ポインタ, 環境}` の **2 語**。インタフェースで避けた「値は 8 バイト」問題がまた出ます |
| 寿命 | 捕まえた変数がクロージャより先に消えると壊れます。所有権の検査が要ります |
| 型注釈 | 引数と戻り型が必須なので `|x: float| -> bool: x > 0.0` と長くなり、短さの利点が薄れます |

**得るものが書き味だけで、払うものが大きい**という判断です。
入れるとしても、インタフェースで書けない場面が実際に出てきてからにします。

| | |
|---|---|
| 保留 | クロージャ。インタフェースで代替できることを確認したため |
| そのとき採る | 捕獲を **所有権の移動だけ**に限る（借用の捕獲は寿命の検査が要る） |

**注意: `raises` する関数は値にできません。** 関数型がエラーの受け渡し
（出力引数 + タグ）を表さないためです。**インタフェース越しは 0.34.0 で
通るようになりました**（A-40）が、そちらは「宣言に書いてある `raises` を
呼ぶ側が見られる」から成り立ちます。関数型にはその欄がありません。表すなら型に `raises` を含める必要があり、
それは別の設計判断になります。

## 4. 演算子の多重定義

### 入れ方：新しいパスも新しい IR も作りませんでした

`a + b` の左辺がクラスで、そのクラスに `__add__` があれば、
**意味解析が `ND_BINOP` を `ND_METHOD` に書き換えます。** それだけです。

```
check_binop
  ├ 左辺の型を検査
  ├ クラスで、__add__ がある？ → ノードを a.__add__(b) に作り替えて
  │                              check_class_method に渡す（ここで終わり）
  └ そうでなければ、今までどおりの型検査
```

- **codegen は 1 行も変えていません。** ふつうのメソッド呼び出しになります。
- 所有権検査・`--drop`・2 実装の IR 一致も、そのまま通ります。
- 注意: 右辺は**メソッドの引数として**検査します。先に `check_expr` すると
  **2 回検査**してしまいます。

`m[i, j]` は、構文解析で添字を **next でつないだ並び**にし
（引数リストと同じ形）、意味解析で `__getitem__` / `__setitem__` に
読み替えます。`m[i, j] += v` の脱糖は、**添字を 1 つずつ隠し変数に**
入れます（対象も添字も 1 回だけ評価する、という 5.2 の約束を守るため）。

### 決めたこと / 捨てたこと

| | 決めたこと | 捨てたもの |
|---|---|---|
| 名前 | Python と同じ `__add__` | `add`（既存メソッドが勝手に演算子になる） |
| 選び方 | **左辺の型だけ** | 反転（`__radd__`）・引数の型での多重定義 |
| `!=` | `__eq__` から導く | 両方書かせること |
| 添字の数 | いくつでも（`__getitem__` の引数と合えばよい） | 2 次元専用の構文 |
