# `{{cc}}` リファレンス

```
{{cc}} [オプション] <入力{{ext}}>
```

コンパイルするのは**入口のファイル 1 つだけ**です。`import` は自動でたどられます。

```bash
{{cc}} hello{{ext}} -o hello
```

---

## 出力

| オプション | 説明 |
|---|---|
| `-o <file>` | 出力する実行ファイル名（既定 `a.out`）。Windows では `.` を含まない名前に `.exe` を足す |
| `-c` | リンクせずオブジェクト（`.o`）を出す |
| `-I <dir>` | `import` を探す場所を足す（何度でも書ける。`-Ideps` の形も可）。パッケージマネージャ [`{{pm}}`](pkg.md) が `deps/` を渡すのに使います |
| `-j <N>` | `clang` を同時に何本走らせるか（既定はコア数、`-j1` で逐次）。⚠️ **出来上がる実行ファイルは並列度で変わりません** |
| `-S` | LLVM IR を標準出力に書いて終了 |
| `--keep-ll` | 実行ファイルを作った後も `.ll` を残す |
| `-O0` / `-O1` / `-O2` / `-O3` | clang に渡す最適化レベル（既定 `-O0`） |
| `--target=<triple>` | 生成する IR の target triple（例 `--target=riscv64-unknown-elf`） |

### `-I` と探索の順番

`import x` を探す場所は 3 つです。

1. 入口ファイルのあるディレクトリ
2. `-I` で足したディレクトリ（書いた順）
3. 標準ライブラリ（`lib/`）

**優先順位はありません。** 2 つ以上の場所で見つかったらエラーにします。
どちらを先にしても「黙って隠れる」ものが出るからです。

## 検査だけする

| オプション | 説明 |
|---|---|
| `--check` | 型検査までで止める。問題が無ければ**何も出さない**（終了コードで判定） |

## 安全性の検査

**既定はすべてエラーです**（0.18.0 から。A-24）。二重解放・解放後の使用の
指摘は、オプションを 1 つも付けなくてもコンパイルを止めます。

| オプション | 説明 |
|---|---|
| `--warn-own` | 所有権の指摘を**警告に落とす**（`E-MOVE-*` / `E-BORROW-*` / `E-MUT-*`）。⚠️ 0.17 以前の既定です。**これを付けたコードは、この言語の安全性の保証の外にあります** |
| `--deny-move` | 移動済みの値の使用をエラーにする（`E-MOVE-1`。**既定**） |
| `--deny-borrow` | 借用した値の保存・返却をエラーにする（`E-BORROW-*`。**既定**） |
| `--deny-mut` | 読み取り専用の借用への書き換えをエラーにする（`E-MUT-1`。**既定**） |
| `--deny-store-borrow` | 借りものを所有スロットへ入れる箇所をエラーにする（`E-BORROW-7` / `E-BORROW-8`。**既定**） |
| `--drop` | スコープの出口に解放を挿入する（**既定**） |
| `--no-drop` | 解放を挿入しない（`--drop` を打ち消す。**後に書いたほうが勝ち**） |
| `--explain-mut` | 呼び出しで書き換えられる実引数を一覧表示して終了 |

**★ `--deny-*` は「`--warn-own` の後に、検査ごとに戻す」ために残してあります。**
**後に書いたほうが勝ちます**（`--drop` / `--no-drop` と同じ規則）。

```bash
{{cc}} app{{ext}} -o app                      # 4 つともエラー（既定）
{{cc}} --warn-own app{{ext}} -o app            # 4 つとも警告
{{cc}} --warn-own --deny-move app{{ext}} -o app # 移動だけエラーに戻す
```

古いコードを持ち込むときは、`--warn-own` で全体を通してから、
通ったものを `--deny-*` で 1 つずつ上げていくのが順序です。

**★ 解放は既定で入ります。** スコープを抜けるとき、そこで所有していた値が
解放されます。何を解放してよいかは所有権検査が決めます（借りものと
移動済みの値は解放しません）。

⚠️ `--no-drop` が要るのは、**わざと危険な書き方をして診断を見せる**ような
場合だけです（この言語のテストがそうしています）。ふつうは付けません。

⚠️ **`spawn` を使ったファイルでは `--warn-own` が効きません。**
所有権の指摘を警告に落とすと「データ競合が無い」という保証も一緒に
警告どまりになるためです（`E-SEND-*` は「借りか・所有か・`rc` か」という
所有権検査の判定にそのまま乗っています）。

なお、スレッドに渡せるかどうかの検査（`E-SEND-1`〜`4`）は**常にエラー**で、
外すオプションはありません。**2 つの実装のどちらでも同じです**（A-25）。

## C のライブラリを繋ぐ

| オプション | 説明 |
|---|---|
| `-l<名前>` / `-L<dir>` | リンクのときに clang へそのまま渡す（`-lopenblas` など） |
| `-framework <名前>` | 同上（macOS の framework。`-framework Accelerate`） |

```bash
{{cc}} -O2 app{{ext}} -framework Accelerate -o app   # macOS
{{cc}} -O2 app{{ext}} -lopenblas -o app              # Linux
```

**★ `extern def` で宣言した関数の実体が標準ライブラリの外にあるとき**に要ります
（[`blas`](../spec/stdlib.md#blas) がその例です）。

🔒 シェル経由で渡るので、`-o` と同じように**入口で 1 回**確かめます。

## デバッグ

| オプション | 説明 |
|---|---|
| `-g` | デバッグ情報を出す（DWARF のもとになる metadata）。⚠️ 付けないときの出力は 1 バイトも変わりません |

```bash
{{cc}} -g app{{ext}} -o app
lldb ./app            # ブレークポイント・バックトレースが行で出ます
perf record ./app     # どの行が重いかが出ます
```

**★ 出るのは「関数の枠」と「行の対応表」です。** 変数の中身（`p x`）はまだ
見られません。止める・たどる・測るところまでが `-g` の範囲です。

⚠️ **macOS では `<出力>.dSYM` も一緒に作られます**（`dsymutil` を自動で
走らせます）。DWARF が `.o` の中に残る仕組みなので、これが無いとデバッガが
何も出せません。消すとデバッグ情報も消えます。

## 情報

| オプション | 説明 |
|---|---|
| `--version` | 版番号・stage・target triple |
| `--print-lib-dir` | 標準ライブラリの場所を表示（パッケージマネージャ [`{{pm}}`](pkg.md) が名前の衝突を確かめるのに使います） |
| `-h`, `--help` | 使い方 |

## 処理系を追う

| オプション | 説明 |
|---|---|
| `--dump-tokens` | トークン列を表示して終了 |
| `--dump-ast` | AST を S 式で表示して終了 |

`--dump-tokens` と `--dump-ast` は**入口のファイルだけ**を見ます（`import` をたどりません）。

## 環境変数

| 変数 | 用途 |
|---|---|
| `PLC_CLANG` | 使う clang（`clang-18` など名前が違うとき） |
| `PLC_RUNTIME_O` | ランタイム（`runtime.a`）の場所 |
| `PLC_LIB_DIR` | 標準ライブラリ（`*{{ext}}`）の場所 |
| `PLC_TARGET_TRIPLE` | 既定の target triple |
| `PLC_CFLAGS` | `-c` のときに clang へ追加で渡す引数 |

**どれも埋め込みの既定値より優先されます。** 既定では、コンパイラは自分の実行ファイルからの
相対（`<exe>/../lib/plc/`）でランタイムと標準ライブラリを探すので、
インストール先がどこでも動きます。

## 終了コード

| 値 | 意味 |
|---|---|
| 0 | 成功 |
| 1 | コンパイルエラー、または clang の失敗 |

コンパイルしたプログラムの終了コードは、`main` の戻り値の**下位 8 ビット**です
（`return -1` は 255 になります。どの OS でも同じ結果になるよう、生成側で切り詰めています）。
