# yashirolang 言語仕様書 v1

> このドキュメントは「yashirolang とは何か」の**唯一の正解**です。
> 実装で迷ったらここに戻ります。仕様を変えたいときは、コードより先にここを書き換えます。
>
> 版ごとの変更は [changelog.md](../changelog.md) に、これからの予定は [roadmap.md](../roadmap.md) にあります。

## 1. 設計方針

yashirolang は次の 4 つの原則で設計します。

1. **見た目は Python** — インデントでブロック、`def`、`:`、`#` コメント。Python を書ける人が読める。
2. **型は静的** — すべての変数・引数・戻り値の型がコンパイル時に確定する。型注釈は必須。
3. **実行時型情報は持たない** — 値は「型タグ付きボックス」ではなく生のマシン値。`int` は `i64` そのもの。
4. **自分自身を書けること** — 言語機能の採否は「コンパイラを書くのに必要か」で判断する。
   必要なら入れる、不要なら入れない。「Python にあるから入れる」は採用理由にならない。

## 2. 字句 (Lexical Structure)

### 2.1 ソースファイル

- エンコーディング: **UTF-8**
- 拡張子: `.ys`
- 改行: `\n`（`\r\n` は読み込み時に `\n` に正規化する）
- ファイル末尾に改行がなくてもよい

### 2.2 コメント

`#` から行末まで。ブロックコメントはありません。

```python
# これはコメント
x: int = 1  # 行末コメントも可
```

### 2.3 論理行と物理行

- **物理行** = ファイル中の改行で区切られた 1 行
- **論理行** = 文法上の 1 行

括弧 `(` `[` `{` の中では改行が無視され、複数の物理行が 1 論理行になります。

```python
x: int = (1 +
          2)          # 1 論理行
```

行末のバックスラッシュによる継続（`\`）は **v1 では未対応**です。

### 2.4 インデント

Python と同じオフサイドルールを使います。

- インデントは **半角スペースのみ**。**タブは字句エラー**とする。
- 推奨インデント幅は 4 だが、言語仕様上は「同じブロック内で一貫していること」だけを要求する。
- 論理行の先頭でインデント幅が
  - 増えたら → `INDENT` トークンを 1 個生成
  - 減ったら → スタックを巻き戻し、戻した段数だけ `DEDENT` トークンを生成
  - 減った先の値がスタックに存在しない → **インデントエラー**
- 空行および `#` だけの行は、インデント計算の対象外（完全に無視する）

**🤔 なぜタブを禁止するのか**
タブ幅の解釈（4 か 8 か）で意味が変わるコードが書けてしまうのは、言語として欠陥です。
Python は歴史的経緯で許容していますが、新しい言語なら禁止すべきです。実装も単純になります。

### 2.5 キーワード

基本の語（未使用のものも予約しておき、将来の追加に備えます）。

```
and      as       break    class    continue def      elif     else
extern   False    for      if       import   in       is       None
not      or       pass     return   True     while
```

安全性のために足した語（[safety-spec.md](safety-spec.md)）:

```
own      mut      raises   unsafe   pragma
```

将来のために予約（使うとエラー）:

```
assert   const    del      except   finally  from     global   lambda
match    nonlocal raise    try      with     yield
```

⚠️ `try` / `except` / `raise` / `assert` には意味が付いています（エラー処理と `assert`）。
残りは**予約だけ**で、使うとエラーになります。

⚠️ **`scope` は予約語ではありません**。`scope:` の次が改行のときだけ
ブロックとして読みます（3.2.1）。`scope` という名前の変数やフィールドは
今までどおり書けます — このコンパイラ自身が使っているためです。

### 2.6 識別子

- 1 文字目: `A-Z` `a-z` `_`
- 2 文字目以降: `A-Z` `a-z` `0-9` `_`
- 大文字小文字を区別する
- 非 ASCII 文字は **v1 では識別子に使えない**（実装を単純にするため）

### 2.7 リテラル

| 種類 | 例 | 型 |
|---|---|---|
| 10進整数 | `0` `42` `1_000_000` | `int` |
| 16進整数 | `0xFF` `0xff` | `int` |
| 2進整数 | `0b1010` | `int` |
| 8進整数 | `0o755` | `int` |
| 浮動小数点 | `3.14` `1e-3` `2.0` `1_000.5` | `float` |
| 真偽値 | `True` `False` | `bool` |
| 文字列 | `"hello"` `'hi'` | `str` |
| None | `None` | `None` |

- `_` は数値リテラル中の桁区切りとして使え、値には影響しない（`1_000` == `1000`）。
- 整数リテラルが `int` の範囲（64bit 符号付き）を超えたら**コンパイルエラー**。
- 文字列は `"` または `'` で囲む。三重引用符は v1 未対応。

#### 文字列エスケープ

| 記法 | 意味 |
|---|---|
| `\n` | 改行 (0x0A) |
| `\t` | タブ (0x09) |
| `\r` | 復帰 (0x0D) |
| `\0` | NUL (0x00) — ⚠️ 3.4 節の注意を参照 |
| `\\` | バックスラッシュ |
| `\"` | 二重引用符 |
| `\'` | 単一引用符 |
| `\xHH` | 16進 1 バイト |

### 2.8 演算子・区切り記号

```

==  !=  <   <=  >   >=
and or  not
&   |   ^   ~   <<  >>
=   +=  -=  *=  //=  %=
(   )   [   ]   {   }
,   :   .   ->
```

## 3. 型 (Types)

詳細な型付け規則は [type-system.md](type-system.md) にあります。ここでは一覧のみ。

### 3.1 プリミティブ型

| yashirolang 型 | LLVM 表現 | サイズ | 説明 |
|---|---|---|---|
| `int` | `i64` | 8 | 64bit 符号付き整数。**あふれたら実行時エラー**（折り返したいときは `wrap_*`） |
| `bool` | `i1`（メモリ上は `i8`） | 1 | `True` / `False` |
| `float` | `double` | 8 | IEEE 754 倍精度 |
| `str` | `ptr` | 8 | NUL 終端 UTF-8 バイト列へのポインタ。**不変** |
| `None` | `void` | 0 | 値を持たない型。戻り値なし関数の戻り型 |

### 3.2 複合型

| 型 | LLVM 表現 | 説明 |
|---|---|---|
| `list[T]` | `ptr`（`{ptr data, i64 len, i64 cap}` を指す） | 可変長配列。参照セマンティクス |
| `dict[K, V]` | `ptr` | ハッシュマップ。標準ライブラリで実装 |
| ユーザー定義 `class` | `ptr`（構造体を指す） | 参照セマンティクス |
| `T \| None` | `ptr`（`null` 可） | Nullable。`class` 型と `str` にのみ適用可 |
| `(A, B)` | `ptr`（`{A, B}` を指す） | タプル。**複数戻り値**に使う |
| `rc[T]` | `ptr`（数え札付きの箱を指す） | 共有所有。`T` はクラスのみ |
| `Thread[R]` | `ptr`（ランタイムの箱を指す） | `spawn` が返す。`join()` で `R` を受け取る |
| `mutex[T]` | `ptr`（ランタイムの箱を指す） | **中身に触るには `lock(f)` を通す**。`T` はクラスかリスト |

⚠️ `Thread[R]` と `mutex[T]` は**キーワードではなく型の名前**です。
`spawn` / `mutex` も同じで、**同名の関数を自分で定義すればそちらが優先されます**
（`rc` と同じ扱い）。新しい構文は 1 つも増えていません。

```python
def work(n: int) -> int:
    return n * 2

def main() -> int:
    t: Thread[int] = spawn(work, 21)   # 別スレッドで始める
    return t.join()                    # 終わるまで待って戻り値を受け取る
```

`spawn` の引数は**何個でも**書けます（始める関数の引数の並びと同じ数）。

### 3.2.1 `scope:` ブロック

```python
scope:
    t: Thread[list[float]] = spawn(rows, a, b, n, 0, 128)   # ★ 借りを渡せる
    part: list[float] = t.join()
# ← ここまでに、始めたスレッドは全部 join されている
```

**ブロックの出口で、そこで始めたスレッドを必ず全部 join します。**
だから中の `spawn` には**借りを渡せます**（借りはこの呼び出しより長生き
しない、という規則が成り立ったままになるため）。

⚠️ `scope` は**予約語ではありません**。`scope:` の次が改行のときだけ
ブロックとして読み、そうでなければ今までどおりの変数宣言です
（`scope: rc[Scope] | None` はそのまま書けます）。

⚠️ ブロックの**途中から抜けることはできません**（`return` / `raise` /
ブロックを越える `break` / `continue` / 捕まえていない失敗しうる呼び出し）。
出口の join が飛ぶと、借りを渡してよい根拠が崩れるためです。

何をスレッドに渡せるかは [safety-spec.md](safety-spec.md) と
[design/concurrency.md](../design/concurrency.md) を見てください。

### 3.3 型注釈が必須な場所

```python
def f(a: int, b: str) -> bool:      # 引数と戻り値：必須
    x: int = 0                       # ローカル変数の初期宣言：必須
    x = 1                            # 再代入：不要（宣言時の型を使う）
    return True

g: int = 10                          # グローバル変数：必須

class Token:
    kind: int                        # フィールド：必須
    text: str
```

**🤔 なぜ型推論を入れないのか**
`x = 0` から `int` を推論するのは簡単ですが、
「型注釈を必ず書く」ルールにすると **型検査器が「調べる」だけになり「推論する」必要がなくなる**ため、
実装が劇的に単純になります。
（v2 以降で局所的な型推論を追加する余地は残します。）

### 3.4 `str` の表現について（重要な設計判断）

v1 の `str` は **C と同じ NUL 終端バイト列**です。

```
  s: str = "abc"
        ↓
  ptr ──→ [ 'a' ][ 'b' ][ 'c' ][ 0x00 ]
```

| メリット | デメリット |
|---|---|
| C の関数（`strlen`, `printf`, `fopen`）にそのまま渡せる | `len(s)` が O(n) |
| ランタイムが極小で済む | 文字列中に NUL を含められない |
| 実装が単純で、初学者が中身を追える | 部分文字列を取るたびにコピーが必要 |

**⚠️ 落とし穴**：`"a\0b"` と書いた文字列の `len()` は 1 になります。
これは仕様上の既知の制限です（コンパイラを書く用途では問題になりません）。

`{ptr, len}` 方式（長さを持つ）への移行は、必要になった時点で改めて検討します。

### 3.4.5 範囲型（部分型。A-28）

`int` に名前と両端を付けた型を宣言できます（Ada の部分型にあたります）。

```python
type Percent = int range(0, 100)     # 両端を含む
type Celsius = int range(-273, 1000) # 下端は負でもよい
```

- **型としては `int` と同じ**です（表現も `i64` のまま）。違うのは
  「その型の場所に入れるときに両端の中にあるかを確かめる」ことだけです
- 確かめる場所：変数の宣言・代入、フィールドへの代入、`list` の要素
  （リテラル・`append`・添字への代入）、仮引数（**関数の入口で 1 回**）、`return`
- **途中の計算は基底型（`int`）で行います**（`p * 2` は `int`）
- 定数は**コンパイル時に**断ります。それ以外は実行時に確かめます
- **検査を外すオプションはありません**
- 端は整数のリテラルだけです（式は書けません）。空の範囲は書けません
- いま範囲を付けられるのは `int` だけです

⚠️ `type` も `range` も**予約語ではありません**。トップレベルで
「`type` の次が名前で、その次が `=`」と並んだときだけこの規則になります。

### 3.4.6 契約（事前条件・事後条件。A-29）

関数の本体の**先頭**に、満たすべき条件を書けます（Ada の `Pre` / `Post`）。

```python
def divide(a: int, b: int) -> int:
    requires b != 0          # 入口で確かめる
    ensures result >= 0      # return のたびに確かめる
    return a // b
```

- `requires` は**関数の入口**で、`ensures` は**`return` のたびに**確かめます
- `ensures` の中では `result` が**戻り値そのもの**を指します
  （⚠️ 特別なのは `ensures` の式の中だけで、`result` という名前の変数は今までどおり使えます）
- 値を返さない関数では `result` を書けません
- 式は `bool` でなければなりません（truthiness はありません）
- 置けるのは**本体の先頭**だけです（順序は自由）
- 破ると止まります：`contract violated: requires of divide (line 2)`
- **検査を外すオプションはありません**
- ⚠️ 引数が範囲型なら、**範囲の検査が先**です（まず型、次に契約）
- ⚠️ `ensures` は `return` の**直前**に評価されます（Ada の `'Old` はありません）

⚠️ `requires` も `ensures` も**予約語ではありません**。次のトークンが
代入・修飾・呼び出し・添字の記号なら、今までどおりの文として読みます。

### 3.5 暗黙の型変換はしない

`int` と `float` を混ぜた演算は**コンパイルエラー**です。明示的に変換します。

```python
x: int = 3
y: float = 1.5
z: float = float(x) + y    # OK
w: float = x + y           # ✗ エラー: int と float は加算できません
```

**🤔 なぜ？** 暗黙変換は型検査器に「どちらに合わせるか」の複雑なルール（型昇格）を要求します。
初学者向けの実装としては、エラーにするのが最も明快です。

## 4. 式 (Expressions)

### 4.1 演算子の優先順位

上が**弱い**（後で結合する）、下が**強い**。同じ行の演算子は同順位。

| 順位 | 演算子 | 結合 |
|---|---|---|
| 1 | `or` | 左 |
| 2 | `and` | 左 |
| 3 | `not x` | 単項 |
| 3 | `==` `!=` `<` `<=` `>` `>=` `in` `is` | 左（連鎖は不可） |
| 4 | `\|` | 左 |
| 5 | `^` | 左 |
| 6 | `&` | 左 |
| 7 | `<<` `>>` | 左 |
| 8 | `+` `-` | 左 |
| 9 | `*` `/` `//` `%` | 左 |
| 10 | `-x` `+x` `~x` | 単項（右結合） |
| 11 | `**` | **右** |
| 12 | `f(...)` `x[...]` `x.attr` | 後置（左） |
| 13 | リテラル、識別子、`(...)` | — |

**⚠️ Python との差異**：Python は `a < b < c` の**比較連鎖**を許しますが、yashirolang v1 では
**構文エラー**にします（`a < b and b < c` と書く）。実装の単純化のためです。

### 4.2 算術演算

| 演算子 | int | float | str | 意味 |
|---|---|---|---|---|
| `+` | ✅ | ✅ | ✅ 連結 | 加算 |
| `-` | ✅ | ✅ | ✗ | 減算 |
| `*` | ✅ | ✅ | ✅ 繰り返し | 乗算。⚠️ `str * int` の順のみ |
| `/` | ✗ | ✅ | ✗ | 真の除算（float のみ） |
| `//` | ✅ | ✗ | ✗ | **切り下げ**除算（int のみ）。負の無限大の方向へ丸める |
| `%` | ✅ | ✗ | ✗ | 剰余。符号は**除数と同じ** |
| `**` | ✅ | ✅ | ✗ | べき乗。int は指数が負なら実行時エラー |

**`float ** float` も使えます。** ランタイムは libc なしで（ベアメタルでも）
動く必要があるため、`pow` は使えません。**`pl_fpow` を自前で置いています**
（`exp(y * log(x))` を級数で計算。`lib/math.ys` の `pow` と同じ結果になります）。

| 式 | 結果 |
|---|---|
| `2 ** 3` | `8`（int。繰り返し二乗法） |
| `2.0 ** 3.0` | `8.0`（float） |
| `2.0 ** 0.5` | `1.414214`（平方根） |
| `2 ** -1` | **実行時エラー**（int では表せない） |
| `2.0 ** -1.0` | `0.5` |

**⚠️ Python との差異**：`int / int` は **エラー**です。Python では `float` を返しますが、
yashirolang は暗黙変換を持たないため、`//`（整数除算）か `float(a)/float(b)` を明示させます。

#### `//` と `%` の符号

**Python と同じ切り下げ（floored）**です。`//` は 0 ではなく**負の無限大**の
方向へ丸め、`%` の符号は**除数と同じ**になります。

| 式 | 結果 | 式 | 結果 |
|---|---|---|---|
| `7 // 2` | `3` | `7 % 2` | `1` |
| `-7 // 2` | `-4` | `-7 % 2` | `1` |
| `7 // -2` | `-4` | `7 % -2` | `-1` |
| `-7 // -2` | `3` | `-7 % -2` | `-1` |

**この 2 つは一組です。** どちらの符号でも次の恒等式が成り立ちます。

```python
a == (a // b) * b + (a % b)
```

⚠️ **C の `/` `%`（LLVM の `sdiv` / `srem`）とは負数で違います。**
C は 0 の方向へ丸めるので `-7 / 2` は `-3` です。yashirolang は
[書きやすさを絶対とする方針](../roadmap.md#0-譲らないこと)に従い、
Python 側に合わせました。0 除算の検査でどのみち `pl_floordiv` を通るため、
**呼び出しの回数は増えていません**（増えるのは関数の中の比較が 2 つだけです）。

#### 桁あふれ

**`+` `-` `*` と単項 `-` は、結果が 64bit に収まらなければ実行時エラーです。**

| 式 | 結果 |
|---|---|
| `9223372036854775807 + 1` | **実行時エラー** |
| `9223372036854775807 * 2` | **実行時エラー** |
| `-(-9223372036854775808)` | **実行時エラー** |
| `2 ** 64` | **実行時エラー** |
| `int(1.0e30)` / `int("99999999999999999999")` | **実行時エラー** |

⚠️ **0.5.x までは 2 の補数で黙って折り返していました。** 仕様にもそう書いて
ありましたが、[§0 の ②](../roadmap.md#0-譲らないこと)（安全性が下がる
書きやすさは入れない）と噛み合わないため、0.6.0 で改めました。

##### 意図して折り返したいとき — `wrap_add` / `wrap_sub` / `wrap_mul`

法 2⁶⁴ の計算（線形合同法など）では、折り返しこそが目的です。
**そこは名前で書き分けます。**

```python
# lib/random.ys の線形合同法
def next_state() -> int:
    STATE = wrap_add(wrap_mul(STATE, 6364136223846793005),
                     1442695040888963407)
    return STATE
```

| | |
|---|---|
| 形 | `wrap_add(a, b)` / `wrap_sub(a, b)` / `wrap_mul(a, b)` |
| 型 | **`int` 専用**。2 引数 |
| 意味 | 2 の補数で折り返す。**検査しない** |

⚠️ **`unsafe:` ではありません。** 折り返しはメモリ安全性の問題ではなく、
「そういう計算だ」という意図の表明なので、演算ごとに名前で示します。

##### 添字の中の算術だけは、報告のしかたが違います

**`xs[i * cols + j]` のように添字の中で計算した場合**、あふれても
その演算のところでは止まりません。**添字の計算が終わったところ**で
`integer overflow in index computation` として止まります。

| | 添字の外 | **添字の中** |
|---|---|---|
| 止まるか | 止まります | **止まります**（変わりません） |
| 止まる場所 | あふれた演算のところ | 添字の計算が終わったところ |
| 診断 | `integer overflow in *` | `integer overflow in index computation` |

```python
xs[a * b + f()]      # a * b があふれても、f() は呼ばれてから落ちます
```

⚠️ **検査を省いているわけではありません。** 折り返した添字が
たまたま範囲内に入っても（`4611686018427387904 * 2` は `0` になります）、
あふれの旗を範囲検査と `and` で潰しているので必ず落ちます。

**なぜそうするのか。** `self.data[i * self.cols + j]` のような小さなメソッドで、
外れの経路の**呼び出しが 2 つ増える**と LLVM のインライン化の見積りを超え、
`linalg.Matrix` の行列積が 2 倍以上遅くなりました。あふれの報告を
もとからある範囲検査に相乗りさせると、呼び出しも分岐も増えません
（[版の記録 0.6.1](../changelog.md)）。

##### コンパイル単位で外す — `--no-overflow-check`

```bash
yashirolang --no-overflow-check prog.ys
```

⚠️ **速さのための逃げ道です。** 実測は
[版の記録 0.6.0](../changelog.md)。

⚠️ **このオプションは float の 0 除算の検査も外します**。
「数の実行時検査を外す」1 つのつまみです。

#### 除算の実行時エラー

| 式 | 結果 |
|---|---|
| `a // 0` / `a % 0` | **実行時エラー**（右辺がリテラル `0` ならコンパイル時に弾く） |
| `-9223372036854775808 // -1` | **実行時エラー**。答えが 64bit に収まらない |
| `-9223372036854775808 % -1` | `0` |
| **`x / 0.0`（float）** | **実行時エラー**（`-0.0` で割った場合も） |

⚠️ 途中の 2 つは C では**未定義動作**で、実際には黙って SIGFPE で落ちます。
yashirolang は名前を付けて落とします。

##### `x / 0.0` を実行時エラーにした理由

0.13.0 より前は `1.0 / 0.0` が `inf` になっていました。**同じ「割る」なのに
`1 // 0` は止まって `1.0 / 0.0` は止まらない**、という揃っていない状態です。
Python はどちらも `ZeroDivisionError` なので、そちらに揃えました。

```python
x: float = 1.0 / 0.0        # ✗ 実行時エラー: float division by zero
y: float = math.inf()       # ✓ 無限大が欲しいときはこれ
```

**⚠️ 費用は測ってあります。** float の除算が主のループ（ライプニッツ級数
2000 万項、-O2）で **+9.8%**（107.5 → 118.0 ms）です。外れの経路の
呼び出しが 1 つ増えるためで（規約 R13）、IEEE754 のままにしたいときは
`--no-overflow-check` を付けます。

**⚠️ `0.0 / 0.0` も止まります**（`nan` になりません）。NaN で**割る**のは
NaN のまま通します — 見ているのは右辺が 0 かどうかだけです。

### 4.3 比較演算

すべて `bool` を返します。両辺は**同じ型**でなければなりません。

- `int`, `float`, `bool`: 値の比較
- `str`: **内容**の比較（`==` は `strcmp(a,b)==0`）
- `class` 型: **参照（アドレス）**の比較
- `is` / `is not`: **`None` との比較にだけ**使える（`x is None` / `x is not None`）
  - 左辺は `T | None` 型でなければならない
  - 一般の同一性比較には使わない（`class` の `==` が既に参照比較のため）

### 4.3.1 nullable と絞り込み

```python
t: Token | None = find()
if t is not None:
    print(t.kind)      # ★ この中でだけ t は Token
```

- `T | None` にできるのは**参照型**（`str` / `list[T]` / class）だけ
- `T` → `T | None` は代入できる（広げる方向のみ）
- `T | None` のまま `.` で触ることはできない（先に絞り込む）
- 絞り込めるのは**ローカル変数**だけ（グローバル変数・フィールドは対象外）
- 絞り込みは**代入で解除**される（`cur = cur.next` のあとは `T | None` に戻る）
- `if x is None: return` のようなガード節の後ろでも絞り込まれる

### 4.4 論理演算

- `and` / `or` は**短絡評価**する。両辺は `bool` 型のみ（`int` を真偽値扱いしない）。
- `not` は `bool` を取り `bool` を返す。
- 結果は `bool`。**Python のように「最後に評価した値」を返さない**（型が一意に決まらないため）。

**⚠️ Python との差異**：`if xs:`（空リストが偽）のような **truthiness は採用しません**。
`if len(xs) > 0:` と明示的に書きます。

### 4.5 関数呼び出し

```python
f(a, b)
```

- 引数の**個数**と**型**が一致しなければコンパイルエラー
- デフォルト引数・キーワード引数・可変長引数は **v1 未対応**
- 評価順は**左から右**

### 4.6 内包表記

```python
[ 式 for 変数 in 対象 ]
[ 式 for 変数 in 対象 if 条件 ]
```

**対象にできるのは `list[T]` と `range(...)`** です。

```python
ys: list[int] = [x * 2 for x in xs]
odd: list[int] = [x for x in xs if x % 2 == 1]
sq: list[int] = [i * i for i in range(5)]
down: list[int] = [i for i in range(10, 0, -3)]
```

- ループ変数は**内包表記の中だけ**で見えます（外の同名の変数は隠しません）。
- **`for` は 1 つだけ**です。入れ子にしたいときは、内側を式として書きます
  （`[v + 1 for v in [y * 10 for y in xs]]`）。
- `range` の**増分は整数リテラル**だけです（`for` 文と同じ。5.5 節）。
- 辞書内包・集合内包はありません（`dict` / `set` は標準ライブラリのクラスで、リテラル構文がないためです）。

> **⚠️ ループ変数は要素を「借りて」います**（`for` 文と同じ）。
> `[s for s in strs]` のように**借りたものをそのまま新しいリストに入れる**と、
> 所有権検査が警告します（E-BORROW-3）。値が要るなら `copy(s)` を使うか、
> 新しい値を作る式（`"v" + s` など）を書いてください。

### 4.7 演算子の多重定義

**クラスは演算子に意味を与えられます。** `a + b` の**左辺**がクラスで、
そのクラスに `__add__` があれば、**`a.__add__(b)` として扱われます。**

```python
class Vec2:
    x: float
    y: float

    def init(self, x: float, y: float) -> None:
        self.x = x
        self.y = y

    def __add__(self, o: Vec2) -> Vec2:
        return Vec2(self.x + o.x, self.y + o.y)

    def __eq__(self, o: Vec2) -> bool:
        return self.x == o.x and self.y == o.y

a + b        # → a.__add__(b)
a != b       # → not a.__eq__(b)
```

| 演算子 | メソッド |
|---|---|
| `+` `-` `*` `/` `//` `%` `**` | `__add__` `__sub__` `__mul__` `__truediv__` `__floordiv__` `__mod__` `__pow__` |
| 単項 `-` | `__neg__` |
| `==` `!=` | `__eq__` `__ne__` |
| `<` `<=` `>` `>=` | `__lt__` `__le__` `__gt__` `__ge__` |
| `m[i]` / `m[i, j]` | `__getitem__` |
| `m[i] = v` / `m[i, j] = v` | `__setitem__`（値が**最後の引数**） |
| `x in c` / `x not in c` | `__contains__`（⚠️ **右辺**の型で決まります） |

- **戻り型は自由です。** `__add__` が別の型を返しても構いません。
- `!=` は `__ne__` が無ければ **`not (a == b)`** になります
  （⚠️ そのとき `__eq__` は `bool` を返す必要があります）。
- `==` を定義しないクラスの `==` は、**これまでどおり同一性の比較**です。

#### ⚠️ 反転（`__radd__`）はありません

**左辺の型だけ**で決まります（`in` を除く。下記）。`2.0 * m` は書けません（`m * 2.0` と書きます）。
どのメソッドが呼ばれるかを、読んで分かるようにするためです。

#### `in` だけは右辺で決まります

`x in c` は**入れ物 `c`** に聞きます（`c.__contains__(x)`）。Python と同じ
考え方です。`not in` は結果を反転させます。⚠️ `__contains__` は `bool` を
返す必要があります。

```python
import dict

d: dict.Dict[str, int] = dict.Dict()
if "a" in d:        # → d.__contains__("a")
    ...
```

#### 2 次元の添字 `m[i, j]`

添字は**カンマで並べられます**。`__getitem__` の引数の数と合っていれば、
いくつでも構いません。

```python
m[i, j]          # → m.__getitem__(i, j)
m[i, j] = v      # → m.__setitem__(i, j, v)
m[i, j] += v     # 対象と添字は 1 回だけ評価されます（5.2 と同じ脱糖）
```

⚠️ **`list[T]` と `str` の添字は 1 つだけです。** `xs[0, 1]` はエラーです。

## 5. 文 (Statements)

### 5.1 変数宣言

```python
x: int = 0
```

- 初期化式は**必須**（未初期化変数を作らせない）
- 同一スコープでの再宣言はエラー
- 内側のスコープでの同名宣言（シャドーイング）は **v1 では禁止**（混乱を避けるため）

### 5.2 代入

```python
x = 1
xs[0] = 1
p.field = 1
x += 1             # 複合代入
```

複合代入 `x op= e` は `x = x op e` に脱糖します（左辺は 1 回だけ評価）。

#### カンマで並べる代入

```python
a, b = b, a          # 入れ替え
a, b, c = c, a, b    # 巡回
x, y = y, x + y      # フィボナッチ
```

**右辺を先に全部読んでから書きます**（隠し変数に入れます）。だから
入れ替えが正しく動きます。左右の数が違えばコンパイルエラーです。

> **⚠️ これは「代入」です。宣言は兼ねません。**
> 宣言も兼ねるのは `q, r = f()`（右辺が**タプル 1 つ**）のほうです。
> `a, b = 1, 2` で新しい変数は作れません（`a: int = 1` と書いてください）。

### 5.3 if / elif / else

```python
if cond:
    ...
elif cond2:
    ...
else:
    ...
```

条件式は **`bool` 型でなければならない**。

### 5.4 while

```python
while cond:
    ...
```

`while ... else:` は未対応。`break` / `continue` が使えます。

### 5.5 for

```python
for i in range(10):
    ...
for i in range(2, 10):
    ...
for i in range(0, 10, 2):
    ...
for x in xs:            # xs: list[T] → x: T
    ...
```

- ループ変数は**その for 文のスコープに自動的に宣言される**（型注釈は不要、要素型から決まる）
- ループ変数への代入は許すが、次の反復で上書きされる
- `range` は特別扱い（イテレータプロトコルは v1 では作らない）

### 5.6 return

```python
return expr
return          # 戻り型が None の関数のみ
return a, b     # 複数戻り値（タプル）
```

- 戻り型が `None` 以外の関数は、**すべての実行経路で return しなければならない**（コンパイル時に検査）

#### 複数戻り値

戻り型に `(A, B)` と書くと、カンマで並べて返せます。

```python
def divmod2(a: int, b: int) -> (int, int):
    return a // b, a % b
```

- タプルは**名前を持ちません**。「並びが同じなら同じ型」です。
- **1 要素のタプルは書けません。** `(int)` は「括弧で囲んだ `int`」と
  区別できないためで、Python の `(1,)` にあたる記法は入れていません。
- 要素に `None` 型は使えません（値が存在しないため）。
- **作ったら変わりません**（`t[0] = v` は書けません）。

#### リテラル `(a, b)`

```python
t: (int, str) = (3, "ok")
a, b = (7, 8)
```

⚠️ **要素が 2 つ以上のときだけ**です。`(x)` は「括弧で囲んだ `x`」で、
Python の `(1,)` にあたる 1 要素のタプルはありません。

#### 添字 `t[0]`

```python
t: (int, int) = divmod2(17, 5)
print(str(t[0]) + " " + str(t[1]))     # → 3 2
```

> **⚠️ 添字は整数リテラルだけです。** 要素は位置ごとに型が違うので、
> 添字が実行時に決まると**式の型が決められません**。
> 範囲外もコンパイル時に落とします（`t[5]` は「要素は 2 個です」）。

#### 5.6.1 分解代入

```python
q, r = divmod2(17, 5)
```

- **宣言も兼ねます。** 型は右辺のタプルから決まります。
- **型注釈は書けません。** `q: int, r: int = ...` と書かせると Python から
  離れすぎるためです（ロードマップ §0 の ③：右辺から決まるものは書かせない）。
- 受け取る名前の数は、タプルの要素数と一致しなければなりません。
- 右辺は**1 回だけ**評価されます。

### 5.7 pass

何もしない文。空のブロックを書くために使います。

### 5.8 式文

```python
print(x)
obj.method()
```

呼び出し式のみ許可します。`1 + 2` のような副作用のない式文は**警告**（v1 では許容）。

### 5.9 関数定義

```python
def name(p1: T1, p2: T2) -> R:
    body
```

- ネストした関数定義は **v1 未対応**（トップレベルとクラス内メソッドのみ）
- 前方参照可（ファイル後方の関数を呼べる。2 パス方式で実装する）
- クロージャ・第一級関数は v1 未対応

### 5.10 クラス定義

```python
class Token:
    kind: int
    text: str

    def init(self, kind: int, text: str) -> None:
        self.kind = kind
        self.text = text

    def is_eof(self) -> bool:
        return self.kind == 0
```

- フィールドはクラス本体の先頭にまとめて宣言する
- **継承なし**（v1）
- インスタンス生成は `Token(0, "")`。`init` メソッドがあれば呼ばれる
- インスタンスは常にヒープに確保され、**参照セマンティクス**（Python と同じ）
- `self` は第 1 引数として明示的に書く（Python と同じ）

**⚠️ Python との差異**：コンストラクタ名は `__init__` ではなく `init`。
ダンダー（`__x__`）記法を導入しないためです。

### 5.11 extern 宣言

C の関数を呼ぶための宣言です。

```python
extern def pl_read_file(path: str) -> str
extern def pl_system(cmd: str) -> int
```

- 本体を持たない（`:` もブロックも書かない。改行で終わる）
- リンク時に C 側の実体に解決される
- **名前修飾（マングリング）を行わない**（C 側で名前が決まっているため）
- **`bool` は引数にも戻り値にも使えない**（`i1` と C の `_Bool` の ABI が
  環境依存になるため。`int` で受けて `n == 1` と書く）
- 使える型：`int` / `str` / `list[T]` / クラス / 戻り値の `None`

**★ `extern` は標準ライブラリ（`lib/*.ys`）の中に閉じ込めるのが作法です。**
利用者は `io.read_file` を使い、C の関数名を知りません。

### 5.12 import

```python
import lexer

def main() -> int:
    t: lexer.Token = lexer.make(1, "hi")
    print(lexer.MAX_KIND)
    return 0
```

- **モジュール名 = ファイル名から `.ys` を除いたもの**（`import lexer` → `lexer.ys`）
- **パッケージ**（A-32）：`import pkg.mod` は `pkg/mod.ys` を探します。
  使うときも `pkg.mod.f()` と**全部書きます**（短い名前で束ねません）
  ⚠️ パッケージの中でも同じです。`pkg/a.ys` から `pkg/b.ys` を使うときも
  `import pkg.b` と書きます（相対 import はありません）
- 探索するのは**入口ファイルのあるディレクトリ**と `-I` で足した場所（と標準ライブラリ）
- `import` は**トップレベルにのみ**書ける（6.3）
- トップレベルの名前は**すべて公開**される（非公開の規約は設けない）
- **他モジュールの名前は必ず修飾して使う**（`lexer.Token`。`Token` とは書けない）
- 型注釈の修飾は **1 段だけ**（`lexer.Token` / `list[lexer.Token]`）
- **モジュール名と同じ名前**の変数・関数・クラスは宣言できない
- **循環 import はエラー**（依存関係は DAG に保つ）

**採用しないもの**：`from X import Y`／`import X as Y`／`from X import *`／
パッケージ（`a.b.c`）。

## 6. プログラム構造

### 6.1 エントリポイント

```python
def main() -> int:
    return 0
```

- `main` は**引数なし**、戻り型 `int` でなければならない
- 戻り値がプロセスの終了コードになる（下位 8bit のみ OS に伝わることに注意）
- コンパイラは `main` を LLVM の `i32 @main()` にラップする

### 6.2 グローバル変数

```python
counter: int = 0
```

- 初期化式は**コンパイル時定数**でなければならない（v1 の制限）
- 関数から自由に読み書きできる（`global` 宣言は不要）

### 6.3 トップレベルに書けるもの

トップレベルに**実行文は書けません**（Python と違う点）。書けるのは：

- グローバル変数宣言
- `def` / `class` / `extern` / `import`
- コメント・空行

**🤔 なぜ？** トップレベルに実行文を許すと「モジュールの初期化順序」という厄介な問題が発生します。
コンパイル言語では `main` を唯一の入口にするのが単純で予測可能です。

## 7. 組み込み関数

| 関数 | シグネチャ | 説明 |
|---|---|---|
| `print` | `(int) -> None`<br>`(str) -> None`<br>`(bool) -> None`<br>`(float) -> None`<br>`(list[T]) -> None` | 標準出力に出力し改行。型ごとにオーバーロード |
| `len` | `(str) -> int`<br>`(list[T]) -> int` | 長さ |
| `str` | `(int) -> str`<br>`(bool) -> str`<br>`(float) -> str`<br>`(str) -> str`<br>`(list[T]) -> str` | 文字列化。`str` からは**複製** |
| `int` | `(str) -> int`<br>`(float) -> int` | 整数化。float からは**0 方向へ切り捨て**（-1.7 → -1） |
| `float` | `(int) -> float`<br>`(str) -> float` | 浮動小数点化。**`str` からは正しく丸めます**（`float(str(x)) == x`）。読めなければ**実行時エラー** |
| `abs` | `(int) -> int`<br>`(float) -> float` | 絶対値 |
| `min` / `max` | `(int, int) -> int`<br>`(float, float) -> float` | 2 つのうち小さい／大きいほう。⚠️ **2 引数のみ**（リストは `linalg.vmin`） |
| `sum` | `(list[int]) -> int` | 総和。⚠️ **int のみ**（`list[float]` は `linalg.vsum`） |
| `hash` | `(str\|int\|float\|bool) -> int` | ハッシュ値。**非負**。⚠️ FNV-1a で暗号用ではない |
| `ord` | `(str) -> int` | 先頭 1 バイトのコード |
| `chr` | `(int) -> str` | 1 バイト文字列を作る |
| `exit` | `(int) -> None` | プロセス終了 |
| `panic` | `(str) -> None` | メッセージを stderr に出して異常終了 |
| `input` | `() -> str`<br>`(str) -> str` | 1 行読む。引数はプロンプト。⚠️ **EOF で `panic`** |

#### `float(str)`

**いちばん近い `float` を返します**（正しく丸めます）。桁を足しながら 10 倍する
素朴な実装だと誤差が積もり、`float(str(x))` が `x` に戻らなくなるため、
十進を M × 10^E の分数として多倍長で割っています。

```python
float("3.14")            # 3.14
float("  -1.5e-7  ")     # 前後の空白は無視
float("inf")             # inf（"Infinity" / "nan" も。大文字小文字を問わない）
float("12.5x")           # ✗ 実行時エラー: float(): not a number
```

**⚠️ 読めない文字列を黙って `0.0` にしません。** C の `atof` はそうしますが、
CSV の列が 1 つずれただけで「0 が並んだ正しそうな表」が出来てしまいます
（`int(str)` と同じ考え方です）。

**⚠️ `float("nan")` は正の NaN です。** NaN は自分自身と等しくないので、
`math.isnan(x)` で調べてください。

#### `print(list)` / `str(list)`

`list` はそのまま出せます。

```python
print([1, 2, 3])          # [1, 2, 3]
print(["a", "b"])         # ["a", "b"]
print([True, False])      # [True, False]
```

**⚠️ 要素が `int` / `float` / `str` / `bool` のときだけです。**
要素の型ごとにランタイム関数を呼び分けているためで、`list[list[int]]` や
`list[MyClass]` はコンパイルエラーになります（`for` でまわしてください）。

`str` の要素は `"` で囲みます。Python の `repr` と同じ考え方で、
`["a b", "c"]` と `["a", "b", "c"]` を見分けられるようにするためです。

### 7.1 `float` の文字列化

`print(float)` と `str(float)` が出す形は **1 か所で定義されます**
（`runtime/core.c` の `pl_ftoa`）。

| 入力 | 出力 |
|---|---|
| NaN | `nan` |
| ±無限大 | `inf` / `-inf` |
| 通常 | **元に戻る最短の桁数**。末尾の 0 は落とすが**最低 1 桁は残す**（`1.0`） |
| \|x\| ≥ 1e18、または 0 < \|x\| < 1e-6 | 指数表記（`1.0e-9`） |

```python
print(1.0)          # 1.0     （1 ではない）
print(0.1 + 0.2)    # 0.30000000000000004   ★ 誤差が見えます
print(1.0 / 3.0)    # 0.3333333333333333
print(0.1)          # 0.1     （17 桁にはなりません）
print(1.0e-9)       # 1.0e-9
```

**✅ 往復します。** `float → str` は
**その double に戻るいちばん短い表記**を選びます（Python の `repr` と同じ考え方）。

> **⚠️ 0.8.x までは小数部 6 桁で丸めていました。** `str(0.1 + 0.2)` が `0.3` に
> 見えるのは、数値計算の言語として害でした（自分の誤差が見えない）。
> **表示のために丸めたいときは `math.round_to(x, 6)`** を使ってください。

> **⚠️ 指数表記の境目は Python と違います。** Python は `1e-5` から指数表記に
> しますが、yashirolang は **`1e-6` 未満**からです（`0.00001` は `0.00001`）。

**🤔 なぜ `print` だけオーバーロードを許すのか**
ユーザー定義関数のオーバーロードは実装しません（名前解決が複雑になる）。
しかし `print` を型ごとに `print_int` / `print_str` と書き分けるのは
教材としてストレスが大きすぎるため、**組み込み関数に限り**コンパイラが特別扱いします。

## 8. 実行時エラー

以下は実行時に検出し、stderr にメッセージを出して終了コード 1 で異常終了します。

| 条件 | メッセージ |
|---|---|
| 0 除算 | `runtime error: division by zero` |
| リスト添字範囲外 | `runtime error: index out of range: i (len=n)` |
| `None` のフィールドアクセス | `runtime error: None has no field` |
| メモリ確保失敗 | `runtime error: out of memory` |
| 範囲型の範囲外（A-28） | `runtime error: value out of range: Percent accepts 0..100 but got 101` |
| 契約違反（A-29） | `runtime error: contract violated: requires of divide (line 2)` |

例外機構（`try`/`except`）は v1 では**採用しません**。回復不能エラーは即終了です。

## 9. メモリ管理

**v1 では解放しません**（`malloc` するのみ、`free` しない）。

**🤔 なぜ？**
GC も参照カウントも、それ自体が大きなプロジェクトです。
そして本命のターゲットである「コンパイラ」は**短命なプロセス**なので、
プロセス終了で OS がまとめて回収するのに任せて問題ありません。

詳細と将来の選択肢は [../design/memory-model.md](../design/memory-model.md) にまとめます。

## 10. Python との差異まとめ

yashirolang を書くときに引っかかりやすい非互換の一覧です。

| # | Python | yashirolang | 理由 |
|---|---|---|---|
| 1 | 型注釈は任意 | **必須** | 静的型付けのため |
| 2 | `int / int` → float | **エラー**（`//` を使う） | 暗黙変換なし |
| 3 | `if xs:` が使える | **`if len(xs) > 0:`** | truthiness なし |
| 4 | `a < b < c` | **エラー** | 比較連鎖なし |
| 5 | `a and b` が値を返す | **`bool` を返す** | 型が一意に決まらない |
| 6 | トップレベルに実行文 | **不可**（`main` が入口） | 初期化順序を持たない |
| 7 | `__init__` | **`init`** | ダンダーを導入しない |
| 8 | 継承・多重継承 | **なし**（`interface` と合成で代用） | 実装単純化 |
| 9 | 例外 | **`raises` / `try` / `except`**（アンワインドしない） | ベアメタルで動かすため |
| 10 | 動的属性追加 | **なし** | 静的レイアウト |
| 11 | タブインデント可 | **エラー** | 曖昧さの排除 |
| 12 | 任意精度整数 | **64bit 固定** | マシン値をそのまま使う |
| 13 | クロージャ・lambda | **関数型 `fn(...)->T` はあり／クロージャは無い** | 捕獲した変数の寿命の検査が要る |
| 14 | シャドーイング可 | **なし** | 混乱の排除 |
| 15 | `(1,)` で 1 要素タプル | **書けない** | `(int)` と区別できない |
| 16 | タプルの添字 `t[0]` | **整数リテラルの添字だけ** | 要素ごとに型が違うので、添字が実行時に決まると式の型が決まらない |
| 17 | `a, b = b, a`（入れ替え） | **書ける**（右辺を先に全部読みます） | — |
| 18 | `input()` が `EOFError` | **`panic`** | 例外はアンワインドしないため |

**`//` と `%` の符号は 0.5.1 で埋めました。** 以前はここに
「`-7 // 2` が Python は `-4`、yashirolang は `-3`」という差がありましたが、
0 除算の検査でどのみち `pl_floordiv` / `pl_mod` を通るため、
**呼び出しを増やさずに** Python と同じ切り下げにできました（[4.2](#42-算術演算)）。

## 11. サンプルプログラム（v1 完成時に動くもの）

```python
# examples/fizzbuzz.ys
def fizzbuzz(n: int) -> str:
    if n % 15 == 0:
        return "FizzBuzz"
    elif n % 3 == 0:
        return "Fizz"
    elif n % 5 == 0:
        return "Buzz"
    else:
        return str(n)

def main() -> int:
    for i in range(1, 16):
        print(fizzbuzz(i))
    return 0
```

```python
# examples/token.ys
class Token:
    kind: int
    text: str

    def init(self, kind: int, text: str) -> None:
        self.kind = kind
        self.text = text

def main() -> int:
    tokens: list[Token] = []
    tokens.append(Token(1, "hello"))
    tokens.append(Token(2, "world"))
    for t in tokens:
        print(t.text)
    return 0
```
