# 本言語言語仕様 v2 — 安全性モデル

> v1（[language-spec.md](language-spec.md)）は「Python の文法で書ける静的型付け言語」でした。
> v2 はそこに **Rust のメモリ安全性**を持ち込みます。ただし **Rust の書きにくさは持ち込みません**。
>
> この文書は v2 で**何を保証し、何を書かせないか**の唯一の正解です。
> 実装は必ずここに従います。仕様を変えたいときは、コードより先にここを直します。

---

## 0. 一行でいうと

> **所有権は「コンパイラが追いかけるもの」であって、「人間が書くもの」ではない。**

Rust の難しさの大半は、安全性そのものではなく
**安全性を人間に宣言させる記法**（`&`, `&mut`, `'a`, `Rc<RefCell<T>>`, `.clone()`, `.borrow_mut()`）から来ています。
本言語は同じ保証を、**注釈をほぼ書かせずに**得ることを目標にします。

| Rust で書くもの | 本言語では |
|---|---|
| `&T` / `&mut T`（借用） | **書かない**。関数引数は既定で借用 |
| `'a`（ライフタイム注釈） | **書かない**。借用は呼び出しより長生きできない、という規則で代用（§4.4） |
| `let mut x`（局所変数の可変性） | **書かない**。再代入は自由（§5.1） |
| `x.clone()` | **書かない**。必要なら `copy(x)`、ただし大半は借用で足りる |
| `Rc<RefCell<T>>` | `rc[T]` ひとつ（§7） |
| `Result<T, E>` + `?` | `raises` + `try` / `except`（§8） |
| `Option<T>` | `T | None`（v1 で実装済み） |
| `unsafe { }` | `unsafe:` ブロック（§10。OS 開発向け） |

**書かせるもの**は 3 つだけです。

1. `own` … 関数が引数の**所有権を奪う**とき
2. `mut` … 関数が引数を**書き換える**とき
3. `raises` … 関数が**失敗しうる**とき

## 1. 保証すること（安全性の定義）

安全な（`unsafe:` の外の）本言語コードでは、次が**コンパイル時に**保証されます。

| # | 保証 | 検出方法 |
|---|---|---|
| S1 | **use-after-move が無い** — 移動済みの値は読めない | ムーブ検査 |
| S2 | **use-after-free が無い** — 解放済みメモリへの参照が作れない | 借用検査 |
| S3 | **二重解放が無い** — 所有者は常に 1 つ | 所有権 |
| S4 | **メモリリークが（実用上）無い** — スコープを抜けたら解放される | drop 挿入 |
| S5 | **データ競合の芽が無い** — 可変借用と他の借用は同時に存在しない | 借用検査 |
| S6 | **null 参照が無い** — `T` は必ず値を持つ。無いなら `T | None` | 既存の絞り込み |
| S7 | **範囲外アクセスが無い** | 実行時チェック（既存） |
| S8 | **エラーの握りつぶしが無い** — 失敗しうる呼び出しは必ず処理される | `raises` 検査 |

**S9整数の桁あふれが無い** — `+` `-` `*` `**` と単項 `-`、
`int(float)` / `int(str)` は、64bit に収まらなければ実行時エラーです。
折り返しが目的のところは `wrap_add` / `wrap_sub` / `wrap_mul` と書きます。
⚠️ 添字の中の算術（`xs[i * n + j]`）は、あふれを**範囲検査と一緒に**報告します
止まることは同じで、診断が `index computation` になります。
**折り返した添字がたまたま範囲内に入っても落ちます**（`and` で潰しているため）。

**S100 で割れない** — 整数の `a // 0` / `a % 0` に加え、
**`x / 0.0`（float）も実行時エラー**です。`-0.0` で割った場合も、
`0.0 / 0.0` も止まります。⚠️ 見ているのは**右辺が 0 かどうかだけ**なので、
`nan` や `inf` で割るのは IEEE754 のまま通します。
無限大が欲しいときは `math.inf()` を使ってください。

> **なぜ揃えたか。** `1 // 0` は止まるのに `1.0 / 0.0` が `inf` になるのは、
> 同じ「割る」で挙動が違うということです。Python はどちらも
> `ZeroDivisionError` なので、そちらに揃えました。費用は測ってあり、
> float の除算が主のループで +9.8% です。

> **✅ コンパイラ自身がこの検査を通ります**。
> `make own-strict` で、指摘をエラーにしたまま `selfhost/` を建て直せます。
> ⚠️ 既定は警告のままです（既存のコードがそのまま動くように。§0 の ③）。

**✅ データ競合も検査します**。`spawn` に渡せるのは `own` した値、
`mutex[T]`、そして **`scope:` ブロックの中でだけ共有の借り**です。
`scope:` の外の借りは渡せず（`E-SEND-1`）、`rc[T]` も渡せません（`E-SEND-2`）。
**可変借用はどこでも渡せません**（`E-SEND-4`。寿命が足りていても、配る先が
重なっていないことを静的に言えないため）。
スレッドから始まる経路でのグローバルの書き換えも止めます
（`E-SEND-3`。⚠️ **呼び先までたどります**）。
**利用者が書く注釈は 1 つも増えません** — 借りか、所有か、`rc` か、という
この章の検査がすでに持っている情報だけで判定しているためです。
⚠️ `spawn` を使ったファイルでは、この章の検査が**自動でエラーに上がります**
（設計は [design/concurrency.md](../design/concurrency.md)）。

**⚠️ 保証しないこと**：`rc[T]` の循環参照によるリーク（§7.4）、`unsafe:` の中身、
`--no-overflow-check` を付けたときの桁あふれと float の 0 除算。

## 2. 値の分類

型は **3 つ**に分かれます。ここが v2 の土台です。

| 分類 | 型 | 代入の意味 | 解放 |
|---|---|---|---|
| **コピー型** | `int`, `float`, `bool` | 値をコピー（元も使える） | 不要 |
| **所有型** | `str`, `list[T]`, `dict[K,V]`, class, `ptr[T]` | **移動**（元は使えなくなる） | 所有者のスコープ終端で解放 |
| **共有型** | `rc[T]` | 参照カウントを増やす | カウントが 0 で解放 |

```python
a: int = 1
b: int = a          # コピー。a はそのまま使える

xs: list[int] = [1, 2]
ys: list[int] = xs  # 移動。xs はここで無効になる
print(len(xs))      # ❌ エラー E-MOVE-1: 'xs' は 3 行目で 'ys' に移動しています
```

**🤔 なぜ Python の参照セマンティクスを捨てるのか**

v1 は Python と同じ「どこからでも同じオブジェクトを指せる」方式でした。
これは**誰が解放するのかが決まらない**ため、v1 は解放そのものを諦めていました（[memory-model.md](../design/memory-model.md)）。
所有者を 1 つに決めることで、初めて「いつ解放してよいか」が静的に決まります。
**共有したい場面は §4（借用）と §7（`rc[T]`）で救います。**

## 3. 所有と移動

### 3.1 移動が起きる場所

| 場所 | 例 | 移動するか |
|---|---|---|
| 代入 | `b = a` | ✅ する |
| 関数の実引数 | `f(a)` | ❌ しない（既定は借用。§4） |
| `own` 引数への実引数 | `f(a)` で `f(x: own list[int])` | ✅ する |
| `return` | `return a` | ✅ する |
| フィールドへの代入 | `self.xs = a` | ✅ する |
| `list.append` の要素 | `xs.append(a)` | ✅ する（コンテナが所有する） |
| `for` の要素 | `for x in xs:` | ❌ しない（`x` は借用） |
| **フィールドからの取り出し** | `b = a.f` | ❌ **できない**（`E-MOVE-2`） |
| 添字からの取り出し | `b = xs[i]` | ❌ しない（`b` は借用。取り出すには `pop()`） |
| グローバルの読み出し | `b = mod.g` | ❌ しない（`b` は借用。グローバルは常に生きている） |

**🤔 なぜフィールドから取り出せないのか**

オブジェクトを解放するときは、フィールドもまとめて解放します。
途中で 1 つだけ持ち出せると、「どのフィールドがまだ残っているか」を
**フィールドごとの実行時フラグ**で覚える必要が出てきます（Rust はそうしています）。
v2 は「フィールドは借りて使う」で足りるので、その複雑さを買いません。
値そのものが必要なら `copy(a.f)` を使います。

### 3.2 移動後の変数

移動された変数は **無効（moved-out）** になり、読むとコンパイルエラーです。
ただし**再代入すれば再び有効**になります（Rust と同じ）。

```python
def take(xs: own list[int]) -> int:
    return len(xs)

def main() -> int:
    xs: list[int] = [1, 2]
    n: int = take(xs)      # xs は take に移動した
    xs = [3]               # ✅ 再代入で復活
    return n + len(xs)
```

### 3.3 分岐で片方だけ移動した場合

合流点で「片方だけ移動済み」なら、その変数は**移動済みとして扱います**（保守的）。
実行時フラグ（drop flag）は §6.3 で解放のためだけに使い、型検査は静的に判定します。

## 4. 借用（書かない借用）

### 4.1 関数引数は既定で借用

```python
def total(xs: list[int]) -> int:   # xs は「借りているだけ」
    s: int = 0
    for x in xs:
        s = s + x
    return s

def main() -> int:
    ns: list[int] = [1, 2, 3]
    print(total(ns))       # ns の所有権は main のまま
    print(len(ns))         # ✅ 使える
    return 0
```

**これが本言語の中心的な決定です。** Rust なら `&Vec<i64>` と書くところを、何も書きません。
実測上、コンパイラ自身のコード（`selfhost/`）でも関数引数の 9 割以上は借用で足ります。

### 4.2 `own` — 所有権を受け取る

コンテナに格納する、寿命を延ばす、破棄するなど、**引数を借りるだけでは済まない**関数は `own` を書きます。

```python
def push_all(dst: mut list[str], src: own list[str]) -> None: ...
class Node:
    def init(self, name: own str) -> None:
        self.name = name       # フィールドに保存する ＝ 所有権が必要
```

**ルール：`own` が必要かどうかはコンパイラが教えます。**
借用引数をフィールドに保存しようとすると、こう出ます。

```
error[E-BORROW-3]: 借用した値をフィールドに保存できません
   --> node{{ext}}:5:9
    |
  5 |         self.name = name
    |         ^^^^^^^^^^^^^^^^ 'name' は借用なので self より長生きできません
    |
help: 引数を 'name: own str' にすると、所有権を受け取れます
```

### 4.3 借用の規則

ある値に対して、同じ時点で成立してよいのは次のどちらかだけです（Rust と同じ）。

- **共有借用が何個でも**（読むだけ）
- **可変借用がちょうど 1 つ**（読み書き）

```python
def swap_first(xs: mut list[int], ys: list[int]) -> None: ...

def main() -> int:
    a: list[int] = [1]
    swap_first(a, a)   # ❌ E-BORROW-5: 'a' を可変借用と共有借用で同時に渡しています
    return 0
```

### 4.4 借用の寿命 — 「呼び出しより長生きしない」

**本言語にはライフタイム注釈がありません。** 代わりに借用の寿命を機械的に固定します。

| 借用の作り方 | 有効な範囲 |
|---|---|
| 関数の引数 | その関数呼び出しの間だけ |
| `for x in xs` の `x` | そのループ本体の 1 反復 |
| ローカル変数の別名（`b = a` を借用として書く手段は無い） | — |

したがって次の 2 つは**書けません**（＝ライフタイム注釈が必要になる状況が発生しません）。

- 借用を **返す**（`-> list[int]` に借用引数をそのまま返す）
- 借用を **構造体のフィールドに保存する**

**🤔 これで不便にならないのか**

なります。Rust なら `&'a str` を返して済む場面で、本言語は `own` を渡すか `rc[T]` を使うか、
インデックス（`int`）を返すことになります。
**その代わり、ライフタイム注釈という言語仕様上いちばん大きな山を丸ごと削除できます。**
これは「Python の書きやすさ」を優先する、意図的な取引です。

**例外（§4.5）：`self` からの借用返しだけは許します。**

### 4.5 `self` からのフィールド借用

メソッドが `self` のフィールドを返すのは、実質的に「自分の一部を貸す」ことなので許可します。
戻り値は **`self` の借用が生きている間だけ**有効です（呼び出し式を超えて保存できません）。

```python
class Lexer:
    src: str
    def source(self) -> str:      # self.src の借用を返す
        return self.src
```

## 5. 可変性

### 5.1 局所変数は自由に書き換えられる

```python
i: int = 0
i = i + 1          # ✅ Rust の 'let mut' に相当するものは不要
```

**🤔 なぜ `mut` を要求しないのか**：局所変数の再代入は**別名（エイリアス）を作らない**ため、
安全性に影響しません。Rust の `let mut` は「うっかり変更」を防ぐための規律であって、メモリ安全の要件ではありません。
本言語は安全性に必要な `mut` だけを残します。

### 5.2 借用を書き換えるには `mut`

```python
def clear(xs: mut list[int]) -> None:
    ...

def show(xs: list[int]) -> None:
    xs.append(1)       # ❌ E-MUT-1: 'xs' は読み取り専用の借用です
                       # help: 引数を 'xs: mut list[int]' にしてください
```

メソッドは `self` に付けます。

```python
class Counter:
    n: int
    def get(self) -> int:        # 読むだけ
        return self.n
    def bump(mut self) -> None:  # 書き換える
        self.n = self.n + 1
```

### 5.3 呼び出し側には何も書かない

```python
c: Counter = Counter()
c.bump()            # Rust の (&mut c).bump() に相当。記法上は Python のまま
clear(xs)           # ✅ clear(mut xs) とは書かない
```

**🤔 「変更されるのが呼び出し側から見えない」問題**：見えないのは事実です。
本言語は「宣言側に書けば十分」と判断します（Python / C++ 参照 / Java と同じ立場）。
代わりに、**IDE 用の情報と診断で補います**（`--explain-mut` で変更される実引数を一覧表示）。

## 6. 解放（drop）

### 6.1 いつ解放されるか

所有している値は、**所有者が有効でなくなる時点**で解放されます。

```python
def f() -> int:
    xs: list[int] = [1, 2]
    return 0
    # ここで xs が解放される（早期 return / break / panic の経路も同じ）
```

解放の順序は**宣言と逆順**（後に作ったものから）。

### 6.2 デストラクタ

クラスに `drop` メソッドがあれば、解放の直前に呼ばれます。

```python
class File:
    fd: int
    def drop(mut self) -> None:
        sys.close(self.fd)
```

`drop` は自分で呼べません（二重解放になるため）。早く手放したいときは `del x` と書きます。

### 6.3 条件付き解放（drop flag）

分岐で移動されたりされなかったりする値は、**1 ビットの実行時フラグ**で解放要否を持ちます。
Rust と同じ方式です。フラグはコンパイラが挿入し、ソースには現れません。

## 7. `rc[T]` — 所有権で書けない構造のための逃げ道

### 7.1 何のためにあるか

木・グラフ・双方向リスト・観測者パターンなど、**所有者を 1 つに決められない**データ構造のための型です。
Rust の `Rc<RefCell<T>>` / `Arc<Mutex<T>>` に相当しますが、**1 つの型に畳んであります**。

```python
node: rc[Node] = rc(Node("a"))
other: rc[Node] = node          # ✅ 移動ではなく共有（カウント 2）
```

### 7.2 借用は実行時に検査する

`rc[T]` の中身を可変で使うとき、**借用規則の検査は実行時**になります（コンパイル時には決まらないため）。
違反すると `panic` します。

```python
with node.borrow() as n:       # 共有借用（複数可）
    print(n.name)
with node.borrow_mut() as n:   # 可変借用（1 つだけ。違反すれば panic）
    n.name = "b"
```

### 7.3 使わなくても書けることを優先する

`rc[T]` は**最後の手段**です。まずインデックス（`list` の添字）で表現できないかを検討します。
コンパイラ自身（`selfhost/`）は `rc[T]` を使わずに書けることを目標にします。

### 7.4 制限

- 循環参照はリークします（弱参照 `weak[T]` は将来検討）
- OS 開発モード（§10.4）では既定で**使用禁止**にできます

## 8. エラー処理 — `raises` と `try` / `except`

### 8.1 見た目は例外、実体は `Result`

```python
def read_config(path: str) -> Config raises IOError:
    text: str = io.read_file(path)      # io.read_file も raises IOError
    return parse(text)                   # ← 失敗すればここで自動的に返る

def main() -> int:
    try:
        cfg: Config = read_config("app.conf")
        print(cfg.name)
    except IOError as e:
        print("読めません: " + e.message)
        return 1
    return 0
```

**アンワインド（巻き戻し）は行いません。** `raises` 関数は内部的に
「成功値 or エラー値」のタグ付きの値を返し、呼び出し側に分岐が挿入されるだけです。
そのため **OS カーネルでもそのまま使えます**（§10）。詳細は [design/error-handling.md](../design/error-handling.md)。

### 8.1.1 `raise` — エラーを起こす

> **⚠️ この節は後から足しました。** §8.1 の例は「失敗が伝播する側」しか
> 書いておらず、**エラーを作る構文がありませんでした**。実装して初めて気づいた欠落です。

```python
def read(path: str) -> str raises IOError:
    if len(path) == 0:
        raise IOError("空のパスです")     # ← エラーを起こす
    return io.read_file(path)
```

- `raise` の後ろは**エラークラスのインスタンス**（ふつうの式）
- `raise` はその経路を終わらせます（`return` と同じで、後ろは実行されません）
- 同じ関数の中の `try` が捕まえるなら、そこへ飛びます（Python と同じ）
- 捕まえる `try` が無ければ、呼び出し元へ伝播します（`raises` の宣言が必要）

### 8.2 握りつぶせない

- `raises E` を宣言していない関数の中で、`raises` 関数を呼ぶ → **コンパイルエラー**
  （`try` で処理するか、自分にも `raises E` を宣言する）
- `try` の `except` が、起こりうるエラー型を網羅していない → **コンパイルエラー**
- 戻り値を捨てても、エラーは捨てられません

### 8.3 エラー型

エラーは**ふつうのクラス**です。継承はありません（v1 に継承が無いため）。
複数のエラーを返す関数は `raises IOError | ParseError` と書きます。

```python
class IOError:
    message: str
```

### 8.4 `panic` との使い分け

| 種類 | 使う場面 | 例 |
|---|---|---|
| `raises` | 呼び出し側が回復できる失敗 | ファイルが無い、入力が壊れている |
| `panic` | プログラムのバグ | 添字範囲外、内部矛盾 |

## 9. None 安全（v1 で実装済み）

`T | None` と絞り込み（`if x is None:` / `and` / `or` / `panic` の後）は v1 で完成しています。
v2 で追加する規則はありません。**Rust の `Option<T>` に相当するものは、すでに手に入っています。**

## 10. 低レベル機能（OS 開発向け・仕様のみ先行）

> 実装は安全機能の後。ここでは**設計の手戻りを防ぐため**に決めておきます。
> 詳細は [design/os-support.md](../design/os-support.md)。

### 10.1 `unsafe:` ブロック

```python
unsafe:
    p: ptr[int] = mem.alloc_pages(1)
    p[0] = 42
```

`unsafe:` の中でだけ許されること：生ポインタの作成・参照外し、`volatile` アクセス、
インラインアセンブリ、`extern` の任意呼び出し、型の再解釈。

**`unsafe:` は借用検査を止めません。** 止めるのは「ポインタ操作の禁止」だけです。

### 10.2 `ptr[T]`

生ポインタ。所有型として扱いますが、自動解放はされません（誰が解放するかは人間の責任）。

### 10.3 ハードウェア向けの宣言

```python
pragma no_runtime          # ランタイム（malloc/printf）に依存しない
pragma target "x86_64-unknown-none"

@naked
def _start() -> None:
    unsafe:
        asm("mov $0x1000, %rsp")
```

### 10.4 プロファイル

| プロファイル | ランタイム | 使える機能 |
|---|---|---|
| `hosted`（既定） | あり | すべて |
| `freestanding` | 最小（`pl_alloc` を差し替え可能） | `rc[T]` は要設定、`print` は不可 |

## 11. 文法の差分（v1 → v2）

```ebnf
(* 引数：own / mut を型の前に置く *)
param        = IDENT ":" [ "own" | "mut" ] type
             | [ "mut" ] "self" ;

(* 関数：raises 節を戻り値型の後ろに置く *)
funcdef      = "def" IDENT "(" [ params ] ")" "->" type [ raises ] ":" block ;
raises       = "raises" errtype { "|" errtype } ;

(* try / except / raise *)
trystmt      = "try" ":" block exceptclause { exceptclause } ;
exceptclause = "except" errtype [ "as" IDENT ] ":" block ;
raisestmt    = "raise" expr ;

(* unsafe と pragma *)
unsafestmt   = "unsafe" ":" block ;
pragmastmt   = "pragma" IDENT [ STRING | IDENT ] NEWLINE ;

(* 型 *)
type         = ... | "rc" "[" type "]" | "ptr" "[" type "]" ;
```

**追加キーワード**：`own`, `mut`, `raises`, `raise`, `try`, `except`, `unsafe`, `pragma`, `del`, `with`

**⚠️ `mut` と `own` は型の位置にしか現れないので、識別子としては引き続き使えません
（v1 のキーワード表に追加します）。** 既存コードで `mut` / `own` を変数名に使っている箇所は
実装時に洗い出します。

## 12. 診断メッセージの方針

安全性のエラーは、**「なぜ駄目か」より「どう直すか」**を先に出します。

```
error[E-MOVE-1]: 移動済みの値 'xs' を使っています
   --> main{{ext}}:7:15
    |
  5 |     ys = xs
    |          -- ここで 'ys' に移動しました
  7 |     print(len(xs))
    |               ^^ 移動後に使われています
    |
help: 移動ではなく貸したいなら、'ys' を作らずに関数へ直接渡してください（引数は既定で借用です）
help: どうしても両方で持ちたいなら 'ys = copy(xs)' か 'rc[list[int]]' を使ってください
```

エラーコード体系：`E-MOVE-*`（移動）、`E-BORROW-*`（借用）、`E-MUT-*`（可変性）、
`E-DROP-*`（解放）、`E-RAISE-*`（エラー処理）、`E-UNSAFE-*`。

**実装済みのコード**（章の順）：

| コード | 意味 |
|---|---|
| `E-MOVE-1` | 移動済みの値を使っている |
| `E-BORROW-1` | 借用した値は移動できない |
| `E-BORROW-3` | 借用した値（借用引数など）をフィールド／リストに保存できない |
| `E-BORROW-4` | 借用した値は返せない |
| `E-MUT-1` | 読み取り専用の借用を書き換えている |
| `E-BORROW-5` | 同じ場所を可変借用と他の借用で同時に渡している |
| `E-BORROW-6` | 借りたものが貸し手より長生きする |
| `E-BORROW-7` | 借りものを**所有する側**へ渡している — フィールド／リストへの保存と、`own` 引数へ渡すこと（⚠️ 既定は警告。昇格は `--deny-store-borrow`） |
| `E-RAISE-1` | 失敗しうる呼び出しを処理していない |
| `E-RAISE-2` | 宣言されていないエラーが漏れる |
| `E-RAISE-4` | `main` に `raises` がある |
| `E-RAISE-5` | 失敗しない `try`（警告） |

**⚠️ `E-MOVE-2` は撤回しました**（フィールドの読み出しは借用。D18）。

## 13. v1 からの移行

既存の 323 テストと `selfhost/`（約 6,600 行）は **v1 の参照セマンティクス**で書かれています。
一度に v2 にすると全部が壊れるので、章ごとに次の順で進めます（[roadmap-v2.md](../roadmap.md)）。

1. 型システムに所有情報を持たせる（**検査はしない**）
2. 新しい検査を **警告**として出す
3. `selfhost/` と `lib/` を新仕様に直す
4. 警告を**エラーに昇格**する
5. `make bootstrap` が通ることを確認する

**★ 各段階で `make test` と `make bootstrap` が緑であることを、次に進む条件とします。**

## 14. 非目標（v2 では作らない）

| 作らないもの | 理由 |
|---|---|
| ジェネリクス（ユーザー定義） | `list[T]` などの組み込みだけで足りている。所有権の検査が固まってから再検討 |
| トレイト / インターフェース | 同上。コンパイラ自身が必要としていない |
| 並行実行（`async` / スレッド） | `Send`/`Sync` 相当の設計が必要。OS が動いてから |
| 借用の返却・構造体への保存 | ライフタイム注釈が必要になるため（§4.4） |
| GC | OS 開発が目標のため |
